# 陪练学习记忆

更新：2026-11-17。适用于纯知识答疑、考纲咨询与刷题，不以有题目作为记忆生效前提。

## 会话滚动摘要

Java 从当前用户所属会话组装上下文：最近消息、上一版摘要、显式关联的主题档案、可见题目及 Java 权威判分，按原逻辑补充绑定版本的考纲引用。默认最近 32 条，每条最多 6000 字符，总历史最多 96000 字符。配置写在 `backend/.env.api.properties`：

```properties
quest.coach.context.history-messages=32
quest.coach.context.history-chars=96000
```

服务端保护范围为 10–100 条、6000–120000 字符。按消息数量与字符双重预算从最新向前取，最终保持时间顺序；这不是 tokenizer 精确计数，也不因为供应商宣称 1M 上下文就无限发送历史。会话展示用的消息列表仍最多 100 条。

讲解同一个 JSON 在 `reply` 后输出 `memory`，不增加专门的摘要模型请求。`summary` 上限 4000 字符，通常 300–800 字；结合旧摘要、当前窗口和本次回答滚动更新。主题的进度、问题、计划各最多 1500 字符，通常 100–300 字。缺失或不合规的记忆保留上一版；正文仍按原有完整 JSON 契约验证，不把断流当成功。

Python 完整验证回复后发送内部 `memory` 事件，Java 仅在最终会话事务里保存到 `state_json.memory`，记录更新时间与覆盖到的消息 ID。新 Harness、兼容流式路径及同步路径均接入；取消、失败、半截正文和重复 requestId 不写入新的记忆。刷新恢复持久化摘要。SQLite 图检查点继续用于执行进度，不承担跨会话记忆。

摘要是可修正的 AI 归纳，不是系统指令、考试官方原文、判分或权限事实源。新用户纠正优先；不能把“已讲解”写成“用户已掌握”，不能总结不存在的分数、复习完成情况或长期个人事实。未作答题仍不公开答案、不外发搜索。

## 学习主题与跨会话续接

对话页“学习记忆”抽屉可新建/选择同科目的学习主题。主题含名称、用户学习目标、当前进度、待解决问题、后续计划。用户明确关联后才向模型提供档案；不会自动猜主题、跨科目召回或合并全部历史。

“新对话继续此主题”创建一段绑定该主题的新对话，使用主题科目；不自动发送首句，也不拷贝旧会话的题目、判分和全部消息。独立新对话仍不关联主题。

主题持久化于 V15 的 `student_learning_topic`；所有查询/绑定/修改/删除均按已鉴权用户隔离。AI 只能更新已关联主题的进度、问题与计划，不能改主题名称、目标、所属者或权限。内部返回的版本号取自 Java 传入上下文，不采用模型自造版本号。

并行会话更新与用户手动编辑使用 `revision` 乐观锁。旧版本的 AI 更新跳过，不覆盖新档案，本会话摘要仍保存；下一轮可读取最新档案继续合并。手动编辑冲突返回 409，需要刷新后核对。

抽屉将摘要标记为“自动更新”，平时聊天无需手动保存；“保存修改”仅提交用户手工纠正的摘要，主题新建与编辑分别显示“创建并关联”和“保存修改并关联”。可以编辑/清空会话摘要、修改档案、取消关联或软删除主题。清空摘要不删除原对话，下次完整回答可重新归纳；删除主题停止后续续接，不删除原对话或其独立摘要。幂等轮次回放会以当前摘要和主题状态刷新记忆字段，避免回放已清空/已删除的记忆。档案记录最近更新来源会话，不提供长期个人事实库或向量记忆检索。

## 接口与升级

普通用户接口以 `/api/v1` 为前缀：

- `GET/POST /coach/topics`，新建正文 `{requestId,subject,title,goal?,progress?,questions?,plan?,revision?}`。
- `PUT /coach/topics/{id}`，编辑正文包含 `subject,title,revision`，其余文字字段选填。
- `DELETE /coach/topics/{id}`，软删除。
- `POST /coach/sessions` 新增可选 `topicId`；省略保持独立会话。
- `PUT /coach/sessions/{id}/topic`，正文 `{topicId: UUID | null}`，关联/取消关联；生成中拒绝修改。
- `PUT /coach/sessions/{id}/memory`，正文 `{summary}`；空字符串清空，生成中拒绝修改。
- 会话响应新增 `memory`、`topic`，旧客户端可忽略；浏览器不接收内部 `memory` SSE 事件，而从最终 `done` 接收已持久化状态。

新增迁移脚本 API resources 与 deploy/migrations 的 `V15__learning_topics.sql` 必须一致；不修改既有 V1–V14。配置中的数据库已于2026-11-17按明确授权升级至 V15，主题功能使用前仍需加载 Java/Python 新代码并联调。升级不创建真实用户主题、不修改已有对话或余额、不启用计量，也不调用付费模型。

## 自动标题与空白草稿（2026-11-16）

PC 新建普通对话（含考纲章节入口和主题续接）使用不落库的欢迎页草稿。`POST /coach/sessions` 的 chat 模式默认预览，返回 `persisted=false`；PC 显式传 `preview=true`，URL 的 `draft=1` 仅标记重新准备欢迎页，不存用户输入或凭据。刷新草稿会重新读取当前偏好，已有正式会话则返回已保存状态。练习模式已有出题/用户开始行为，继续直接保存；显式 `preview=false` 保留已有调用方的预创建兼容路径。

首次有效发送携带 `draft:{topicId:null|UUID}`，Java 在同一事务中创建会话、保存用户首句并认领轮次。首次输入必须通过原有验证；草稿不能提交答案、不能复用已删除或他人会话。三种生成路径消费首句标记而不重复追加；模型故障时真实首句仍保留。无输入的新建/刷新/离开不写入会话表，也不出现在历史列表；不对旧库执行空会话清理。

标题随正常完整回答的 `title` 字段生成（通常6–16字，最多32个Unicode字符），经内部事件传递并在最终会话事务中保存。缺少或不合规标题不影响正文、不额外重试模型；首次输入先给出最多24字的临时标题。完整生成一次后不因后续跑题或模型自带标题而反复重命名。侧栏列表、刷新恢复和最终响应显示同一标题。旧请求摘要在新增可选 draft 字段为空时保留原序列化字段，避免升级后影响历史轮次防重。

本部分沿用现有会话 `title` 和 `state_json`，不新增迁移、不依赖 V15；主题续接本身仍需 V15。当前数据库暂不可用，未连接或升级真实库、未调用付费模型，使用隔离 H2 与模型替身验证。
