# 下一阶段开发路线：从账号后台到个人刷题闭环

更新：2026-11-08。面向主项目后续开发及各IDE会话交接。本文是优先级路线，不代表对应功能已实现，也不授权自动写入共享数据库或操作NAS。

## 1. 当前落点

### 已实现/已有证据

- Java27 / Spring Boot4.1.2用户模块：登录、登出、改密、首次强制改密、Admin创建/启停/重置普通用户、JWT+数据库会话撤销；本机Java61项测试通过的基线。
- 群晖Flyway V1–V4已明确授权执行并核验。用户随后自行初始化首个Admin并反馈成功；不要重跑bootstrap或创建默认账号。
- PC真实登录/用户管理、角色路由、localStorage凭据恢复（必须先向me核验）、友好中文Message反馈。用户自行运行API和PC，不自动终止IDE进程。
- Admin外壳与学习页面分离，顶部一级/左侧二三级菜单、全宽卡片、2px圆角、头像下拉、700px自动同步折叠、40px Footer；字体在线思源系列与本地降级。
- 当前前端93项测试和lint/格式/类型/双端构建的验证记录；真实Chrome隔离检查过Admin响应式与登录页多视口，不等同完整真实账号E2E。
- NAS的PG、Redis、SILO、RocketMQ已部署，连接/认证/注册验证见群晖服务验证文档。并非所有业务适配器已接入。

### 仍不能宣称完成

- 普通用户真实私有题库、知识点管理、题目CRUD、练习/错题/收藏/模考、用量统计。
- S3预签名上传业务、真实对象写读删除与跨用户文件隔离。
- MQ可靠Outbox/消费者/重试死信、Embedding/RAG、完整Agent SSE/OCR导入。
- 全流程真实浏览器用户验收、PG会话锁的全面故障/并发验收、共享Redis限流。

## 2. 下一项推荐开发：私有题库与客观题基础闭环

**不要继续增加后台装饰或先堆AI工具。先让一个普通用户能建库、录题、保存，并证明另一个用户和平台Admin看不到。**

建议切成可独立验收的三次交付：

1. 考试/科目基础分类 + 我的题库创建/列表/编辑/归档 + 用户归属安全模型。
2. 本人题库单选/多选的录入、编辑、预览、状态/版本管理。
3. 本人题库练习 → 提交答案 → 确定性判分 → 解析与错题/收藏。

完成这三步后，平台才有第一条真实学习链路，AI导入才有稳定的内容落点。

## 3. 开发前先锁定的结构

产品范围以[私有题库计划](superpowers/plans/2026-11-07-private-question-banks.md)为准：

```text
平台共享考试分类（无公共题目）
├── 事业编A类备考方向 → 职测
└── 上海公务员市考   → 行测

普通用户
└── 本人多个私有题库（建议每库一个考试+科目）
    └── 本人客观题 / 版本 / 文件 / 导入 / 学习记录
```

- 综应、申论仅未来方向，本期不增加主观题、材料题组、主观作答或AI评分。
- Admin创建用户、只看用量/数量，不看题库名称、内容、附件、作答和对话；Admin不能刷题或代用户登录。
- 基础知识点目录与题库集合分开，题目可多知识点，年份/地区/来源是元数据。
- 同名题库、相同题干在不同用户之间也不自动合并、共享或查重暴露。

实施前应形成明确决策，以下是**待定建议，不当作用户已批准**：题库归档/删除规则、题目是否只归一个库、跨库移动/复用、知识点是否用户可自定义、单题审核/发布由本人怎样确认。推荐先采用单库归属+归档优先，避免自动级联删除学习历史；真正改变用户行为的选项再确认。

## 4. 分阶段任务与验收

### P0：账号模块实际验收与安全收尾（不扩功能）

- [ ] 用户浏览器验证Admin开户→普通用户首次改密→登出→重置/禁用后旧会话失效，记录实际结果。
- [ ] 核对显式可信代理配置；Vite/Nginx必须覆盖X-Quest-Client-IP，不直接信任XFF，保持既有账号/来源限额。未配时代理共享限额是已知保守行为。
- [ ] 确认退出误报过期修复，过期/401仍拒绝访问；浏览器存储禁用或网络失败不恢复缓存角色。
- [ ] 后端中文/错误语义与前端友好提示一致，Admin不输出用户私有内容；不把页面隐藏视为唯一权限证明。

不阻塞私有模型设计，但正式交付前必须有实际验收，不用不断自建真实账号“证明”测试；涉及测试写入先说明范围。

### P1：私有题库模型和“我的题库”页面（下一轮编码重点）

后端：
- [ ] 审查当前NAS业务数据与既有无归属字段，再设计新的增量迁移；V1–V4不可重写。
- [ ] 建模考试/科目/题库及owner关联，约束跨用户/跨库引用；旧无归属题目不能默认公开或塞给首个用户。
- [ ] 用户题库API从认证身份取得owner，不接受前端owner_id授权；普通用户只能自己的资源，平台Admin拒绝内容API。
- [ ] 明确API查询层与PG约束/RLS/受限视图是否组合采用；没有实现不要宣称数据库级行隔离。

前端：
- [ ] 普通用户专属“我的题库”，考试/科目切换、列表、创建/编辑/归档；采用现有Arco主题与UI规范，不套Admin账号管理权限。
- [ ] 无公共题库入口，不展示未实现科目或假题目数量；空态引导创建。

验收：
- [ ] A/B账号分别建库，同名可区分归属；A篡改资源ID不能读取/修改/归档B的库。
- [ ] Admin不能通过内容接口查看题库，即使手动输入URL；普通用户不能用户管理。
- [ ] 分页/筛选/重复提交/并发写冲突有稳定行为；迁移与权限副本一致。

### P2：题目编辑与版本

- [ ] 单选/多选题干、2–8连续选项、答案、解析、难度、知识点与来源管理。
- [ ] 接口按题库所属授权，不能通过questionId/版本ID绕过用户检查；关联知识点/试卷同样验证。
- [ ] Markdown安全渲染；用户题目不可经Admin查询、诊断日志或未授权文件URL泄漏。
- [ ] 题目修改的乐观并发/快照与历史练习引用语义明确，答案/解析在学习前不可意外泄露。
- [ ] 先文本手工题闭环，不因图片上传、OCR或AI暂未完成就用假内容占位。

验收：用户能录入并重开查看真实题；非法答案拒绝；另一个用户和Admin均不可读；并发编辑不会静默丢更新。

### P3：练习、判分、错题和收藏

- [ ] 开始本人题库练习、下一题、提交、解析；未提交的题DTO不携带正确答案/解析。
- [ ] 后端确定性判分，客户端只提交所选答案；多选全对/少选分值按显式规则，不让LLM判分。
- [ ] 会话/答案引用题目版本，防重复作答和并发重放，答题写入与事件Outbox原子。
- [ ] 错题/收藏仅本人可见，按Asia/Shanghai业务日统计，接口时间UTC。

验收：建库→录题→练习→判分→错题再练全链路，刷新/重复提交不重复计数，跨用户会话/答案ID无越权。

### P4：文件上传与LangGraph文本导入

- [ ] Java实现受限应用凭据S3适配、类型/大小限制、私有附件元数据归属、短时预签名URL；不给浏览器root或应用Secret。
- [ ] 以专用测试key验证上传/下载/清理和权限负向，明确授权后再写NAS；CORS按真实origin配置，不开放匿名写。
- [ ] 保持题目图片私有，新私有题库需求优先于早期“公共图片桶”示例；对象前缀不是唯一权限控制。
- [ ] 将现有Python admin scope改为受认证的个人内容导入职责，区分平台Admin；Java校验工具授权并传播真实用户。
- [ ] LangGraph抽取→校验→本人草稿→确认采纳，模型不能直接发布，失败原因/成本可追溯且不泄露原文。

Embedding/RAG到需要语义检索时再接，模型ID/维度明确；现表1024维，换模型不能混用已有向量。

### P5：Admin用量统计与异步可靠性

- [ ] Admin只返回题库/题目/作答/导入/AI/文件等已定义口径的聚合数量，不返回名称、标题、文件名、内容、下载URL或明细穿透。
- [ ] 先做有真实来源的数据，删除/归档/重试/幂等计数规则明确；不展示伪0、伪费用或预测结果。
- [ ] 实现并验证MQ Outbox Relay、同key顺序、消费幂等/事务、重试/死信/补偿，不以Broker注册替代消息可靠性。
- [ ] 当前NAS磁盘约90%告警用户暂不处理；消息写入若受保护阈值拒绝必须如实报告，不擅自调高阈值或清理文件。

## 5. 各IDE会话分工

| 范围 | 工程 | 主要责任 |
|---|---|---|
| Java/API | IDEA打开backend/api-java并关联common | 身份/归属、事务、判分、持久化、S3/MQ/AI业务入口 |
| Python AI | PyCharm打开backend/ai-python | 受控LangGraph、解析/模型适配、索引，不直接写业务题表 |
| PC/mobile/shared | WebStorm打开frontend | UI、路由、API契约、SSE/Markdown、表单与角色工作区 |
| 全局 | 主项目docs/deploy | 需求/接口/迁移兼容副本、环境验证与交接 |

先写精确接口和DTO，再分工，防止两个会话各自发明字段。开工先看git status和局部CLAUDE.md，不覆盖其他会话改动；不自动停止用户IDE进程。

## 6. 运行和开发规则

- 应用本机运行，复用NAS，不在群晖部署应用或重复启动中间件。
- 各子工程有独立配置；不打印真实.env/properties、Token或预签名URL。
- Java日常关闭Flyway；新迁移单独授权执行，平台Admin账户管理与PG超级用户是两层权限。
- 不为新功能增加匿名bootstrap、演示管理员或全局“super_admin绕过”。
- API统一响应/traceId，登录用户提示只展示友好中文，内部诊断保留关联，不直接吐traceId到普通登录提示。
- UI新页面先读[UI规范](../frontend/docs/UI规范.md)，不要重新设计一套按钮/字体/导航；网络字体不可用按约定本地降级。

## 7. 下一轮推荐开工清单

1. 阅读最新私有题库计划与实际schema，输出P1详细模型/接口/测试计划。
2. 把“考试/科目 + 我的题库”作为单独可验收交付，不混入主观题、AI评分或公共库。
3. 本机隔离测试先行，前后端实现、独立权限审查，全量检查通过。
4. 单独列出新迁移影响并申请NAS写入授权；升级成功后由用户自行重启IDE API。
5. 用A/B普通用户和Admin验证归属隔离及真实建库，再进入P2手工录题。

后续文档状态应基于真实结果更新；本路线中的待办不因代码存在就勾完成。
