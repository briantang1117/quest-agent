# 下一阶段开发路线

更新：2026-11-11。实现事实依据当前源码、依赖清单和测试核对；不以旧文档推定运行状态。

以下是根据代码缺口整理的建议顺序，不是已实现功能或本次新增开发承诺。当前以个人本机使用为主，先验证已有闭环，再扩范围。

| 优先级 | 工作                        | 完成标准                                                                                                 |
| ------ | --------------------------- | -------------------------------------------------------------------------------------------------------- |
| P0     | 本机真实模型工具联调        | 重启Python/API后验证search→fetch→回答、来源刷新、超时/不支持工具降级；确认实际供应商tool_calls格式       |
| P0     | 核对真实数据库及MQ条件      | 只读确认Flyway历史、pgvector扩展、资料Topic/Worker开关，再按需执行缺失升级与消息验收；不从旧文档猜已部署 |
| P0     | 新编排真实验收              | 加载Java/Python新代码，验证固定提交、文本确认、取消/断网后判分保留、重复轮次及本机SQLite重启读取；不自动重放模型调用 |
| P0     | 长会话与资料闭环            | 幂等重复提交、断网/取消、资料生成失败/重试、删除源会话后下载权限都可复现验证                             |
| P1     | 多来源导入接线              | 扫描PDF、图片/手机截图接OCR、分段、证据、审核UI；已有OCR/候选图不能替代整条业务链                        |
| P1     | 类似题与学习反馈            | 题目向量索引、只返回题干选项的相似题工具、错题/收藏/学情统计，保证答前不泄露答案                         |
| P1     | 考纲范围与检索优化          | 按真实需求扩适用范围多选；有数据规模后再做PG向量ANN、混合召回/重排，保留版本约束                         |
| P2     | 个人多题库                  | 归属模型、CRUD、导入配额与跨链路隔离，复用公共导入但不共享私人内容                                       |
| P2     | 移动端真实接入              | 复用账号/Coach/shared契约，再做移动作答与资料体验，当前仅骨架                                            |
| P2     | 成本与运维                  | 每次模型请求token/费用、速率/并发预算、可观测性、实际备份恢复；需要时才接Redis和S3                       |
| 后续   | MCP / 应用能力包 / 长期记忆 | 有真实复用需求再提供工具发现/鉴权/超时、可版本化能力包、在已实现滚动摘要/主题续接基础上扩展受控长期个人事实记忆                                 |

不优先扩张主观题、商业支付或复杂模考。旧SQL里的会员/订单/统计等表不构成这些能力已完成的证据。

后台扩展先完成前端、协议及离线验证；数据库可用后再按[账号与用量联调清单](后台账号与用量管理.md)授权执行V14并验证续期、日志、强制下线、按模型累计额度与高级功能开通。之后再考虑WebAuthn/Passkey，与iOS“密码”App同步的通行密钥及Face ID免密登录；当前仅支持系统密码管理器自动填充。
