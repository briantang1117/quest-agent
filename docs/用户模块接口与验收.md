# 用户模块第一阶段：接口与验收约定

状态：本地实现/回归与群晖V4迁移已完成（2026-11-07，明确授权后执行）；尚未创建首个Admin或做真实浏览器业务验收。用户当前IDE进程需自行重启加载新Java源码。

本轮范围和方案见 `superpowers/plans/2026-11-07-user-module.md`；产品权限以私有题库后续计划为准。

## 身份与权限

| 操作 | 匿名 | 首次改密用户 | Admin | Student |
|---|---|---|---|---|
| 登录 | 允许 | 允许 | 允许 | 允许 |
| me / logout / change-password | 拒绝 | 允许 | 允许 | 允许 |
| 创建/启停/重置普通用户 | 拒绝 | 拒绝 | 允许 | 拒绝 |
| 用户列表（账号元数据） | 拒绝 | 拒绝 | 允许 | 拒绝 |
| 学习/个人题库/个人Agent | 拒绝 | 拒绝 | 拒绝 | 后续业务实现时允许本人数据 |
| 公共注册/HTTP初始化Admin | 不提供 | 不提供 | 不提供 | 不提供 |

Admin和Student类型互斥，不因Admin身份获得私有内容访问。首轮后台不包含题目/会话/文件内容，也不捏造未落地题库数量。私有题库模型和统计另行迭代。

## API

前缀 `/api/v1`，统一响应 `{code,message,data,traceId}`；HTTP状态与错误语义匹配。

### 公共类型

```typescript
type UserRole = 'admin' | 'student'
type UserStatus = 'active' | 'disabled'
interface UserProfile {
  id: string
  username: string
  displayName: string
  role: UserRole
  status: UserStatus
  mustChangePassword: boolean
  createdAt: string
  lastLoginAt: string | null
}
interface TokenResult {
  accessToken: string
  expiresAt: string
  user: UserProfile
}
```

所有ID以JSON字符串输出，防JavaScript整数精度丢失；时间ISO-8601 UTC。登录密码不做自动trim，不在响应/日志/审计返回hash、明文或完整token。

| 方法 | 路径 | 请求 | data |
|---|---|---|---|
| POST | /auth/login | username,password | TokenResult |
| GET | /auth/me | — | UserProfile |
| POST | /auth/logout | {} | null |
| POST | /auth/change-password | currentPassword,newPassword | TokenResult |
| GET | /admin/users | page,size,keyword,status | list,total,page,size |
| POST | /admin/users | username,displayName,initialPassword | UserProfile |
| PATCH | /admin/users/{id}/status | status | UserProfile |
| POST | /admin/users/{id}/reset-password | newPassword | UserProfile |

用户列表仅普通用户，不通过此接口创建或修改Admin。分页page>=1、size1–100。

用户名：小写ASCII字母开头，3–32位，后续小写字母/数字/下划线。展示名首尾去空白，长度1–64。密码12–64字符，UTF8编码<=72字节，bcrypt；不提供默认口令。

错误码：40000参数、40100登录/会话无效、40300权限、40310需先改密、40400用户不存在、40900用户名冲突、42900限流、50300持久化认证模块不可用。

## 会话规则

本轮采用2h短期JWT加服务端数据库会话，不包含Refresh Token。按用户后续要求，PC持久化token/expiresAt/baseURL到localStorage，刷新后先请求/auth/me校验才恢复身份，不保存密码或信任缓存角色。过期、401、登出清缓存；不会因持久化延长后端会话。localStorage暴露于同源脚本，生产后续可独立升级HttpOnly Cookie与刷新轮换/CSRF方案。

- 登录失败统一文案，未知用户名/错密码/禁用账号不公开具体原因。
- 新建或管理员重置的普通用户必须首次改密；改密前不能调用用户管理/学习功能。
- 登出撤销当前会话；改密/重置撤销旧会话；禁用使已有token立即不可用。
- 权限从数据库身份和会话取得，不信任浏览器角色，也不把自签role声明当作授权。
- 后端失败关闭；数据库会话查询失败不能放行为无状态JWT模式。
- 默认提供进程内登录限流，账号10次/15min、来源60次/15min，当前不放宽；来源已拒请求不得污染账号限额。正式多副本/跨重启限流需共享Redis并测试，不能称已具备分布式限流。
- 代理来源使用专用X-Quest-Client-IP，代理必须覆盖为真实socket peer，不能透传客户端头；后端仅对显式quest.security.login.trusted-proxies中的精确IP读取该单值IP头。默认不信任任何代理、不信任XFF；Nginx已覆盖专用头，Vite需同样覆盖。生产应限制API入口只允许可信代理；开发loopback代理信任需操作者显式配置，不能自动信任所有局域网。
- 未配置可信代理时仍按TCP peer保守限流，Vite/Nginx后会共享来源额度；不能宣称已自动做到真实客户端独立限流。

## 数据迁移和Admin初始化

新结构以V4追加，不重写已执行V1–V3。当前V4草案为旧用户增加account_type/must_change_password/last_login_at并建立auth_session；为避免旧角色歧义，**V4会禁用全部历史app_user并要求改密，不会自动把旧super_admin角色提升为新Admin**。执行前必须检查现有账号并明确批准这一影响。迁移文件与显式Admin初始化入口尚待最终实现验证，**本文件本身不批准执行远程迁移/创建真实用户**。

首个Admin只能通过显式一次性非Web操作建立，需要独立用户名/强密码，不内置默认值、不能在普通API启动时自动创建，不提供匿名bootstrap接口。运行/迁移账号与平台Admin互不等价。

## 验收顺序

1. 本地单测/集成测试，无NAS写入：用户存储、bcrypt、JWT与会话撤销、强制改密、角色矩阵、密码/DTO边界、并发与错误脱敏。
2. PC回归：真实接口mock契约、路由守卫、登录/登出/改密、创建/启停/重置、旧请求不得恢复失效身份；lint/format/test/typecheck/build。
3. 独立安全审查，并为确认缺陷补红绿用例。
4. 明确获批后：NAS V4迁移、权限断言、创建首个Admin，不用真实用户内容做测试。
5. 用户自行重启IDE API，浏览器按Admin开户→新用户登录→改密→登出/禁用的顺序验收；任何临时账户或测试写入都先说明，不自动清库。

只有第4/5步完成才能说当前群晖/IDE环境里的用户模块已端到端可用。现有服务Running不意味着它已重载本轮Java代码。
