# 群晖配置与验证边界

更新：2026-11-11。实现事实依据当前源码、依赖清单和测试核对；不以旧文档推定运行状态。

仓库声明的默认NAS地址为192.168.3.40。以下来自Compose/.env.example，不是本轮探测结果；真实端口与运行版本应从运行配置和服务查询确认。

| 服务     | 仓库配置                      | 本机开发示例端口                    |
| -------- | ----------------------------- | ----------------------------------- |
| PG       | pgvector/pgvector:0.8.2-pg16  | 15432 / quest                       |
| Redis    | redis:7.4.12-alpine           | 16379                               |
| 对象存储 | pgsty/silo固定发布版+摘要     | S3 19000 / console19001             |
| MQ       | apache/rocketmq:5.3.1单broker | NameServer9876 / Broker10911及10909 |

角色：PG运行用quest_app、迁移用quest_owner，quest_ai受限；Worker不需要业务库凭据。脚本V1–V13的存在和双副本一致，只证明仓库准备好；实际Flyway历史与权限需要只读查询。不要重建库或重跑首次Admin初始化。

只读验证顺序：连通性→服务自身健康→应用账号最小必要查询/权限→API deployment readiness→各业务最小合成测试。服务UP不等于消息发收、对象写入、RAG或业务升级已通过。

MQ当前开发配置不启用ACL，Topic不自动创建；NAS防火墙与可信局域网是必要前提。SILO桶策略样例只覆盖quest-public/quest-private，但实际账户/匿名策略不能由JSON文件证明。Redis已有密码/AOF配置，应用目前没有完整Redis适配。

本次未SSH NAS、迁移、创建Topic、写对象或处理磁盘。部署具体说明见[部署导航](../deploy/README.md)，已有环境不以新模板覆盖。
