# 考纲适用范围改多选：待实施记录

记录日期：2026-11-09。**用户明确要求现在不改，等做申论时再实施。** 本文只是设计备忘，不是已实现能力。

## 问题

当前考纲章节的 `scope` 是**单值**枚举：

```text
excluded | vocational_aptitude | administrative_aptitude
```

但考纲存在**总述型章节**，同时作用于多个科目。例如上海 2027 公共科目：

> 上海市2027年度考试录用公务员公共科目笔试包括《行政职业能力测验》和《申论》，全部采取闭卷考试方式，主要测查报考人员从事公务员职业应当具备的基本素质和潜在能力……《行政职业能力测验》为客观性试题，考试时限120分钟，满分100分。《申论》为主观性试题，考试时限150分钟，满分100分。

这段「考试性质、时长、分值」对**行测和申论都成立**。当前实现只能二选一或排除，AI 建议 `excluded`，用户在界面只能选择排除——**信息被丢弃**。

用户判断：这类总述应当保留，并对两个科目同时生效。

## 目标模型

`scope` 从单值改为**多选集合**：

```text
subjects: [] | ["vocational_aptitude"] | ["administrative_aptitude"]
        | ["vocational_aptitude","administrative_aptitude"]
```

- 空集合等价于当前的 `excluded`（仅保留原文）。
- 检索按"集合包含当前科目"过滤，而不是等值匹配。
- 总述章节可同时归属多个科目，不再被迫二选一。

保留 `enabled` 作为人工启用开关，与范围正交：**范围决定"属于谁"，启用决定"是否可用"**。

## 影响面（实施时需逐项处理）

### 数据结构
- `syllabus_version.sections_json` 内每段的 `scope` 字段 → `subjects` 数组。
- `syllabus_chunk.subject` 单列 → 该片段对每个归属科目各写一行，或改为数组列 + 包含查询。
  建议**每科目一行**，保持现有 `WHERE subject=?` 索引可用。

### 后端校验
- `SyllabusService.sections()`：`scope.equals(...)` → `subjects.contains(subject)`。
- 启用条件：集合非空、且 ⊆ 该考试允许的科目集合。
- `SyllabusPipeline.validateSuggestion()`：同样放宽为集合校验。
- `SyllabusChunks.split()`：按集合展开为多条 chunk。

### 前端
- 章节编辑弹窗的范围选择：单选 → 多选（Arco checkbox 或 Select multiple）。
- 列表展示：显示为标签组，例如「行测 · 申论」。
- 需补测试：多选保存、只读回显、非法组合拒绝。

### 迁移
- 新增 V12，把历史 `scope` 迁移为 `subjects` 数组（`excluded` → `[]`，单值 → 单元素数组）。
- 不改 V10/V11（已执行）。

### AI 整理
- 提示词与结果 schema 从 `scope` 改为 `subjects`。
- **AI 只能建议，不能自动启用**——用户已多次强调。
- 需要一条确定性规则辅助：正文同时出现两个科目名称且属于总述时，建议双科目而非排除。
  该规则应可测试、可复现，不依赖模型判断。

## 验收标准（实施时）

- 总述章节可标记为「行测＋申论」，保存后回显正确。
- 行测会话检索命中总述章节；申论会话同样命中。
- 单科目章节不会被另一科目检索到。
- 空集合章节不进入任何检索，但仍保留原文可查。
- 历史数据迁移后行为与迁移前一致（`excluded` 仍不检索）。
- 不因多选而放宽权限：仍只能检索本人有权访问、已发布、已启用的内容。

## 为什么现在不做

用户当前只做行测，申论尚未纳入产品范围。现在改会波及：

- 已执行的 V10/V11 表结构（需新迁移）
- 章节编辑、校验、切片、检索全链路
- 大量前后端测试

在只有行测的场景下，总述章节被排除**不影响实际使用**，因为行测正文自带完整考查范围。等真正接入申论时一并实施，避免半成品状态。

## 当前临时处理

界面仍只能单选。遇到总述章节：

- 若该考试只做一个科目，可暂时选该科目（语义上略宽）。
- 或保持排除，等本次改动完成后修正。

两种处理都不影响已实现的行测检索，因为总述内容与行测正文章节高度重叠。
