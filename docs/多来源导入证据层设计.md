# 多来源导入证据层设计与执行记录

## 目标与边界

依据公共题库计划与会话交接，在现有Python本地解析之上统一PDF页、图片和手机截图的来源表示。题号可空，候选题可跨页/跨图片；保留原始材料与原答案/解析，不把个人作答、统计、导航混入模型输入。不修改Java/数据库、不开放上传路由、不自动外发真实文件。

本次取舍：先提供可验证的证据契约和显式分段组装，不用截图专用坐标/颜色/标题规则冒充通用识别。分段可来自后续视觉模型或人工审核；本轮只接受调用方明确标记的语义片段。没有可靠分段的材料留在证据层，不猜是一题，不自动生成答案。

## 契约

- `SourceEvidence`：证据ID、来源ID（Java后续提供的内部标识，非URL）、输入SHA256、证据种类（PDF页/图片）、序号、可空页码、原文、可空原图引用、警告。
- `EvidenceSegment`：证据ID、原文起止字符偏移、角色。允许题目正文、原答案、原解析、个人作答、界面噪声；偏移是文本字符位置，不冒充图片bbox。
- `assemble_candidate(evidence, segments, question_no=None)`：按指定片段顺序组装一道已明确边界的候选题；引用必须存在、偏移必须有效，个人/界面片段不进入模型输入，原答案和原解析单独保留。无法识别或冲突的答案加阻断警告，全部待审。
- `QuestionCandidate`兼容旧PDF候选入口，增加可空题号、证据引用、原解析。原有PDF正则仍只是来源适配器，不作为手机截图识别器。
- LangGraph保留证据引用和原解析；与原答案冲突的模型解析只进诊断来源，不覆盖原文解析。

## 独立审查修复记录

- 同行个人作答：PDF适配器截去个人答案标签至行末的后缀，原始证据不改；新增模型/搜索输入不含合成私人标记回归。若后缀混有公共内容也会暂时丢弃，交人工对照原文，不猜边界。
- 非标准XObject：提取前拒绝非Image/Form资源，避免pypdf按非Image解码绕过预算。
- 共享Form DAG：缓存子图高度、独立检查每条路径深度，不以解码去重代替路径预算。
- PDF原解析：识别明确解析标题并保存到独立字段，重建候选保留字段；未识别版式仍须人工复核。
- 含糊标准答案：整字段匹配，A或B/A（存疑）/A至D不再取A前缀，阻断模型填补。
- 抽取数量不符：保留已发生的搜索状态、链接、时间，便于失败项审核。

## 无答案材料：联网建议与导入人确认

用户明确要求只有题目时主动websearch找答案并让导入人确认正确性。当前候选图支持注入独立SearchProvider：原答案缺失才检索，每题最多一次、最多3条，正文前128字符作为初始查询（后续需改善长题查询规划），只将有界标题/URL/摘要作为不可信资料供模型参考，不把网页当指令。无配置/无结果/限流错误均记录状态且不自动重试、不泄漏上游错误；模型建议仍是ai_generated，不假冒原答案或web_verified。

每份草稿含原材料证据、原答案/模型答案、来源链接和检索时间，强制`confirmation_status=pending_importer_confirmation`与警告。Java后续需把这变成真实状态机：待确认→导入人修改或确认→审核发布，记录确认人/时间/版本；浏览器传确认状态不能直接让Python或Java信任。来源冲突、无可靠依据、年份/法规不适用应突出待核验，允许暂存/排除，不要求导入人盲选。

本轮已再对原PDF做只读离线回归：3页、13道候选、题号1–13，第4/9题跨页引用保持，cloud_calls=0；未新建报告或覆盖原样本。

当前只实现检索证据收集，不声称网页相关性、原题匹配或建议答案事实正确已自动核验。尚未实现多来源交叉核验/网页fetch细读、来源冲突结构化展示、Java确认门禁或前端审核页；这些必须在端到端发布前补齐。真实截图未调用付费模型，回归使用合成内容与替身搜索。
