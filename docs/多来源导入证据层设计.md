# 多来源导入证据层现状

更新：2026-11-11。实现事实依据当前源码、依赖清单和测试核对；不以旧文档推定运行状态。

已存在的代码是证据模型、候选组装与受控候选图，不是完整的多来源上传产品。核心入口：Python`app/parser/source_evidence.py`、`app/agent/candidate_graph.py`及`app/parser/question_candidates.py`，前端证据字段通过公共题库契约传递。

文本/PDF候选需要保留原文、来源、题号、引用和歧义；模型输出先验证题型/选项/答案，再形成草稿，不直接发布。缺原答案时可由搜索提出有来源的候选，但未经人工确认不能当作权威答案；原答案/原解析不能静默覆盖，未取得证据不能标记核验成功。

当前公共业务入口实际覆盖非结构化文本和文本层PDF；OCR适配器虽存在，扫描PDF/图片/截图上传、自动分段、跨来源冲突到审核UI还没有完整接线。个人题库复用该机制也尚未实现。

后续验收应覆盖：OCR误字、混排题号/选项、答案缺失/冲突、网页注入、来源时间、模型猜测与原文的区分、人工确认版本、错误不发布。陪练search/fetch是另一条只读答疑路径，不能宣称它完成了导入证据流水线。
