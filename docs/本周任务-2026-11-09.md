## 目标与分工

**AI 决定练什么，Java 可靠地执行选题、保存快照并判分。**

个人 Agent 不只是随机出题器，也可以纯答疑；不能将所有对话强行引导到刷题。后台“一个题库=一份试卷”不限制学员跨试卷练习。

- AI：理解“类似、难一点、换个角度”等意图，识别考点、解法与易错点，提出练习策略；必要时比较候选题。
- Java：根据当前用户和会话执行受控查询，只取当前科目已发布、未删除的题，排除已练题，校验候选题合法性，保存出题快照，确定性判分。
- 前端：渲染后端提供的题卡和快捷建议，不写死练习策略或自行生成题目。

## 本周任务（待完成）

### 1. 明确选题意图与接口

- [ ] 区分普通下一题、同考点练习、同解法练习、提高／降低难度、换个角度等请求。
- [ ] 将模型的选题建议转成有界、可验证的结构化条件，而不是让模型生成 SQL 或直接操作数据库。
- [ ] 保留当前练习策略，使普通“下一题”可直接沿用，不必每次重复调用模型。
- [ ] 明确策略在会话内的保持、更新及用户切换要求后的行为。

### 2. 从已审核真题中找类似题（优先交付）

- [ ] 核对现有题目的知识点、难度等元数据质量，确定最小可行筛选方案。
- [ ] 根据当前题的考点、解题方法和易错点找类似题，不只匹配题干字面相似度。
- [ ] 支持“再来一道类似的，但难一点”，跨试卷取题并排除已出题。
- [ ] 必要时让 AI 对有界候选集排序；最终题目必须来自 Java 授权的候选集。
- [ ] 无合适候选时明确说明缺少题目，不悄悄编题或假称找到了类似真题。
- [ ] 只有标签筛选确实不足时，再评估语义检索／向量接入；不默认引入新中间件或重建现有索引。

### 3. 上下文相关的快捷建议

- [ ] 刷题后按上下文提供“练一道同考点”“换个角度”“提高难度”等建议。
- [ ] 纯答疑时提供“举个例子”“解释区别”等合适建议，不硬塞“下一题”。
- [ ] 模型提供候选，Java 校验动作及状态后下发，前端循环渲染；点击即发送对应意图。
- [ ] 建议与完整回答一起保存，刷新后不丢失，位置在最新一条回答下方。

### 4. 单次会话导出为知识文档

2026-11-10 范围更新：用户确认首版仅 Markdown、预留 PDF；经 LLM 提炼而非原文流水导出，顶部“学习资料”统一管理，对话按钮／自然语言触发文件卡片。用户明确要求实践 RocketMQ，使用 Outbox 投递、独立 Worker 消费、API 受控执行。当前实施中，见[学习资料设计](superpowers/specs/2026-11-10-learning-materials-design.md)与[实施计划](superpowers/plans/2026-11-10-learning-materials.md)，不将本地实现描述为真实 MQ 已验收。

用户新增需求：把**单次会话内的题目与讨论内容**导出为 Markdown（`.md`）或 PDF，沉淀成可回顾的知识点资料，而不只是查看聊天历史。

- [ ] 在个人 Agent 会话中提供导出入口，支持 Markdown 与 PDF 两种格式。
- [ ] 导出当前会话的题目、选项、本人作答、已揭示的正确答案／解析，以及相关追问和回答；保留题目与讨论的关联。
- [ ] 将讨论整理为便于复习的知识文档，涵盖核心概念、解题思路、易错点及相关题目；不能只丢失上下文地拼接聊天文字。
- [ ] 保留可追溯的题目／原对话内容；若使用 AI 归纳知识点，区分归纳与原文，不改写 Java 权威判分，不把模型补充当成已核验事实。
- [ ] 导出只读取本人单次会话，不混入其他会话或其他用户内容；未作答题不因导出而提前泄露答案。
- [ ] Markdown 保留标题、列表、公式等结构；PDF 保证中文、公式、长选项及分页可读，不截断正文。
- [ ] 以已保存的完整会话快照为准，生成中的半截 SSE 不当作完成回答导出；无题目的纯答疑会话也能形成文档。
- [ ] 实施前明确“原文导出”与“AI 知识整理”的具体呈现、是否组合提供，以及 PDF 的生成方式；本条仅记录需求，不提前限定技术方案。

## 后续方向：AI 变式题（非本周优先交付）

“找类似真题”和“照这题编一道”必须分开：

- 类似真题：从已审核、已发布题库选择，沿用已有标准答案与解析。
- AI 变式题：模型新生成，明确标注来源，另行校验题干、选项、答案和解析是否自洽，不伪装成真题或自动发布到公共题库。
- Java 比较用户选项只能证明是否匹配标准答案，不能证明模型生成的标准答案本身正确。

本周优先做好类似真题检索；生成题的质量校验、存储与发布边界需另行设计。
