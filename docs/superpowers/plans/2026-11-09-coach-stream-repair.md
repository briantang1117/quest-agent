## 协议与实现顺序

1. Python：短结构化意图路由；一次模型 JSON 流，服务端增量提取正文，完整校验后发送建议。验证 stop、[DONE]、非空、大小界限，任何截断不报告完成。
2. Java：`POST /api/v1/coach/sessions/{id}/turns/stream` 接收原 Turn，复用 requestId 幂等及 processing 互斥。明确 answer/next 不识别意图；自由 chat 先路由，再按需流式回答。答题结果先保存并发送 state；完整正文与建议入库后才 done。中断不回滚已保存判分。
3. Java 资源边界：有界并发，无独立付费 explain HTTP 入口；上游读取有截止时间、断开取消和响应大小界限；成功与失败均审计。
4. 前端：一次业务请求，state/delta/reset/done 协议；本人消息立即展示，done 替换权威会话；切换会话取消并隔离所有回调。建议来自后端，放在最新消息下方。
5. 回归：重复生成、刷新丢回答、建议丢失、EOF伪成功、并发重复、跨用户/跨会话、断流判分保留、取消与失败审计。

## 事件

- state：完整 CoachSession，processing=true；包含已保存用户消息与判分。
- delta：`{text}`，仅用于临时显示。
- reset：`{}`，放弃临时生成文字。
- done：已持久化完整 CoachSession，processing=false。
- error：安全业务错误，无模型原文或密钥。
