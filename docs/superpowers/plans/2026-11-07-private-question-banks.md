# 用户体系与私有题库后续开发计划

日期：2026-11-07。状态：**讨论结论已记录，尚未开始实现；不是已上线能力清单。**

依据：用户本轮明确要求。本文件对原《AI刷题平台-第一期方案》中的统一运营题库、管理员内容管理等假设进行范围修订；未修订的技术约束继续适用。本文是产品与架构层面的后续计划，具体DDL、接口、逐项实施测试需在业务开发前细化。

## 1. 已确认要求

### 1.1 用户与Admin分离

- 用户账号由Admin创建，**不开放自助注册**。
- 普通用户使用平台学习功能，每位用户拥有自己的私有题库，支持创建多个题库。
- 本期不提供通用/公共题库，不提供跨用户共享或题库市场。
- Admin在PC后台管理用户，可查看每位用户的使用情况和统计数量，**不查看具体私有题库内容**。
- Admin账号不提供刷题功能，不把Admin实现成同时拥有全部学习权限的超级学员。
- 不能仅隐藏前端入口：后端也必须限制Admin调用用户内容/练习接口。

### 1.2 考试与科目方向

用户当前准备方向：

| 用户表述 | 本期客观题科目 | 未来科目，仅记录方向 |
|---|---|---|
| 全国事业编A卷 | 职测（职业能力倾向测验） | 综应（综合应用能力） |
| 上海公务员市考 | 行测（行政职业能力测验） | 申论 |

**本期仅单选、多选。** 用户已明确：先不做主观题，综应/申论只是说明未来可能的产品结构。

- 不开发主观题编辑器、材料题组、文字作答、评分要点、自评或AI主观评分。
- 不以本轮讨论为理由增加主观题表、接口、页面或开发排期。
- 可以在设计中保留未来考试/科目扩展的方向，但本期不得把综应/申论展示成已可用功能。
- “全国事业编A卷”是用户原始表述；建议展示为“事业单位联考A类”，具体适用范围/年度考试大纲需后续校准，不宣称全国所有事业单位使用同一试卷。

## 2. 建议采用的数据结构（方案建议，具体建模尚待细化）

```text
平台考试分类（不含题目）
├── 事业编A类备考方向
│   └── 职测（本期）
└── 上海公务员市考
    └── 行测（本期）

普通用户
└── 私有题库（多个，每库建议绑定一个考试+科目）
    ├── 私有题目（单选/多选）
    ├── 导入批次与附件
    └── 基于本人内容的练习/试卷/错题/收藏/学情
```

### 2.1 分类与内容分开

- 平台可提供考试、科目及基础知识点目录；**共享分类不是公共题库**，不意味着有共享题目。
- 建议每个私有题库属于一个考试下的一门科目，第一期不做跨科目题库。
- 知识点与题库分开：题库是用户内容集合，知识点是学习分类；一道题可关联多个知识点。
- 年份、地区、来源、真题/模拟作为元数据/筛选维度，不强制用户为每种组合建立文件夹。
- 建议支持在同一考试科目下跨本人多个题库进行知识点练习；不能跨用户选题。
- 职测与行测目录分别维护，知识点名称相似不等于同一考试分类；跨考试知识点映射以后再评估。
- 用户能否自定义知识点、题目与题库是一对多还是多对多、题库删除与题目迁移规则，留待具体模型设计，不在本轮擅自决定。

### 2.2 平台账号与基础数据

建议采取显式账号类型/能力边界，而不是全局super_admin绕过所有检查。是否保留原方案细分的content_admin/reviewer/operator等角色，需按新的“个人内容+平台Admin”模式重新评估，不直接照搬运营人员查看全库的权限。

Admin本人如需学习，建议另用普通用户账号，禁止通过后台“切换成用户”或模拟登录绕过私有边界；目前这是一条设计建议，最终账号管理细节后续细化。

## 3. Admin PC后台

### 3.1 用户管理

已确认Admin开户。建议同阶段实现：

- 用户列表与账号状态。
- 创建账号、启用/禁用、重置登录凭据。
- 首次登录修改密码、安全初始凭据交付和管理员初始化机制。
- 对创建、禁用、重置等管理操作记录审计。

密码规则、会话失效机制、删除账号与数据保留/清除策略仍需细化。建议禁用优先保留数据，永久删除不作为随手点击的普通操作。

### 3.2 使用统计（用户已确认“看使用情况/统计数量”，下列具体指标是候选）

| 分类 | 候选可见字段 | 不应返回 |
|---|---|---|
| 账号活动 | 创建时间、状态、最近登录时间 | 密码/Token/会话凭据 |
| 题库资源 | 题库数、题目总数、单选/多选数量 | 题库名称、题干、答案、解析、笔记 |
| 学习活动 | 作答次数、练习次数、模考次数 | 具体作答记录、试卷内容、文字原文 |
| 导入 | 批次数、成功/失败数量 | 原始文件、文件名、导入原文、草稿内容 |
| AI | 调用次数、Token量、可核算费用 | Prompt、模型完整响应、对话标题/内容 |
| 文件 | 文件数量、存储总量 | 对象key、下载URL、私有附件 |
| 分类使用 | 各考试/科目使用数量 | 可回溯到题目详情的明细 |

这是指标候选集，不表示本期全部实现或必须展示；先完成数量口径，再按需要补趋势。没有采集的数据不伪造为0或估算成真实费用。

- 统计页不提供“点击数量进入用户题库/题目详情”的穿透入口。
- 同时限制API返回字段、导出、日志和管理工具，不仅隐藏页面。
- 正确率、薄弱知识点等个人学情默认仅本人可见；Admin是否有必要获得此类分析不得从“使用情况”自动推导。
- Admin与数据库超级账号是不同层次：应用权限能限制后台，但不能声称已对拥有NAS/数据库超级权限的运维人员实现密码学意义的不可读。

## 4. PC和移动入口调整

### 普通用户PC工作区

我的私有题库、题目编辑/导入、Agent、练习、试卷、错题、收藏、个人学情和账号设置。**个人录题/导入管理属于普通用户工作区，不放到仅Admin可用的用户管理后台。**

### Admin PC后台

用户管理、用户用量统计、管理审计。无刷题、模考、私人题库编辑、内容预览或私有附件下载入口。

### 移动端

沿用原方案“普通用户Agent”为主，本期不扩成移动管理后台。Admin移动登录的具体处理后续确定，但不得自动进入学员Agent或获得学习权限。

当前`/practice`、`/admin`、`/admin/agent`仅是旧骨架，后续需按新职责重新规划；**现在尚未改路由/API**，不要把原`scope=admin`解释成允许平台Admin访问用户内容。

## 5. 隔离与安全要求

私有化是全链路不变量，不只是question增加user_id：

1. 题库、题目、版本、试卷、导入、附件、会话、作答、收藏、错题、统计均有可校验的所属关系。
2. 用户身份取自已验证认证上下文；客户端传入owner_id/user_id不能授予访问权。
3. 访问任何资源ID必须验证归属；关联题目/知识点/试卷时防止跨用户拼装引用。
4. 向量搜索和全文查询在检索阶段就限定用户，不全库检索后只在UI过滤；Python数据库账号的读取方式需要随之重设计，不能沿用“可读所有业务题库表”就宣称用户已隔离。
5. AI工具scope必须区分平台管理与个人内容管理，个人导入不再要求平台Admin身份。提示词不是权限控制，Java工具执行端验证真实用户。
6. 去重默认只在本人允许范围内进行，不能泄露其他用户是否有相同题目；本期不跨用户合并实体。
7. MQ事件/Outbox保留可信的用户与资源归属；消费者、重试、索引重建不能丢失边界。
8. 缓存键和幂等键包含必要用户范围，防止跨账号复用结果。
9. S3对象通过用户归属授权，预签名URL由后端校验后发放。两个项目桶仍可共用，但必须按私有内容要求设计对象前缀/授权；不为每个用户随意建桶。
10. 私有题目图片原则上也不应因为放在quest-public就匿名公开；新私有题库需求优先于原方案图片公共桶示例，后续明确调整存储规则，不擅自修改现有桶策略。
11. Admin统计走独立聚合接口，不能复用带“管理员绕过”的内容查询API。
12. 应用日志/管理审计避免收录题目/原文/完整对话；异常、监控、导出与备份同样不能成为后台内容窥探入口。

数据库RLS、受限视图/函数或Java查询层隔离采用何种组合，在详细设计时比较；未实现前不宣称有数据库级行隔离。共享数据库连接池中的用户上下文若采用RLS必须事务内安全设置/清理，防串号。

## 6. 对现有底座的影响（均待实现）

- 当前question等表没有完整私有题库模型，需要新增题库实体、归属及约束；现有V1–V3已经在NAS成功执行，**不可修改旧迁移冒充升级，后续使用新迁移版本**。
- 现有角色字典/权限与新账号分离规则不一致，需有意识迁移，不给Admin叠加student权限。
- 当前Python抽取接口仅接受admin scope，与个人内容导入新需求冲突；后续改为真实用户授权下的受限个人导入，保留内部HMAC，不给浏览器服务凭据。
- 当前Java仅JWT验证/系统信息/健康，尚无正式登录及用户管理，不代表已有用户业务可直接复用。
- 当前学员/后台页面是空壳，需要补用户题库管理与Admin用户后台；不挪用题库管理权限给平台Admin。
- NAS当前表数据和历史记录需先检查再做归属迁移，不能假定所有表为空；历史无归属记录不得自动成为公共题或分给第一个用户。
- 数据库写入/账号初始化/桶策略修改及模型真实调用等后续操作，分别说明影响和授权范围，本文件本身不授权远程执行。

## 7. 实施顺序与验收抓手

这是后续分阶段计划，不与正在进行的IDEA Maven修复混在一起。

### 阶段A：账号与私有边界详细设计

- [ ] 明确账户类型、登录/禁用/首次改密、Admin安全初始化和用户创建流程。
- [ ] 确定考试/科目/题库模型、用户归属及现有表迁移策略。
- [ ] 定义Admin统计字段与隐私不可见字段，修订API/Agent scope职责。
- [ ] 输出具体实施计划和测试，审查新DDL后再申请NAS迁移授权。

### 阶段B：真实账号系统

- [ ] Admin创建账号、普通用户登录、凭据重置、禁用后会话失效。
- [ ] PC登录后按账号类型进入正确工作区。
- [ ] 后端拒绝Admin作答/读取用户内容，普通用户不能调用用户管理接口。

### 阶段C：个人题库和客观题闭环

- [ ] 考试/科目基础分类（职测、行测），个人多个私有题库。
- [ ] 用户录题/编辑/导入/采纳、单选多选校验、版本快照。
- [ ] 本人题库练习、确定性判分、错题/收藏和个人学情。
- [ ] LangGraph个人导入/答疑工具的身份传播及检索隔离。

### 阶段D：Admin用量统计

- [ ] 先实现题库/题目/导入/作答等可验证数量，再扩AI成本/存储统计。
- [ ] 为按天用量指定Asia/Shanghai边界，接口时间仍UTC；明确时区、去重、重试和删除数据的口径。
- [ ] 用户只有聚合统计，不泄露内容、标题、文件名或明细跳转。

### 必须包含的权限回归

- [ ] 用户A不能读取/修改/删除用户B的题库、题目、文件、会话、作答或历史版本。
- [ ] 用户A导入、查重、RAG、缓存命中、索引重建和消息重试不能引用用户B数据。
- [ ] 平台Admin可以创建/禁用用户并读统计，但不能读取具体题干/附件/会话，不能作答。
- [ ] API直接请求与页面入口限制一致；不以“无按钮”替代安全测试。
- [ ] 同名题库、相同题干、并发请求、跨用户资源ID/关系篡改都不能破坏隔离。
- [ ] 综应/申论不出现可提交的主观题功能；不增加本期主观评分承诺。

## 8. 后续需要细化而非当前阻塞的问题

- 初始密码交付方式、用户名规则、改密要求与会话生命周期。
- 题库名称/数量上限、删除/归档、题目跨库移动/复用语义。
- 考试显示名与正式大纲版本、知识点目录及用户能否扩展。
- Admin首期展示哪些用量、统计延迟与数据保留期限。
- 身份/私有题库与原审核发布状态机如何对应，不强加平台Admin人工阅读审核。

这些不是要求用户现在逐项作答；后续具体开发时优先给出合理建议，再确认真正影响行为的选择。
