# 对话整理为学习资料：首版设计

日期：2026-11-10。状态：用户已确认总体方案，补充要求所有 LLM 均为 1M 上下文，并明确使用 RocketMQ 实践；实施中，未授权新数据库迁移或远程 MQ 资源修改。

## 1. 用户已明确的目标

- 学员顶部增加独立入口，汇总本人各个对话生成的材料。
- 对话上可以主动触发整理；输入“把本次对话整理成材料／学习材料／复习材料”等自然表达，也能创建生成任务。
- 必须经大模型提炼知识点、解答、例题等，生成可独立阅读的学习材料，不能只是拼接聊天记录。
- 对话内显示文件卡片，点击可下载；资料列表能查到所有对话生成的 Markdown。
- 首版只做 Markdown，预留 PDF；保存方式由实现方决定。
- 用户说明当前文本模型上下文为 1M，整理功能要使用独立的大上下文预算，不能复用普通聊天仅最近若干轮的截断方式。本次未通过真实模型调用验证供应商窗口。
- 本次范围更新为首版仅 Markdown、PDF 预留，替代本周早期同时实现 Markdown/PDF 的排期。
- 先提交已有代码再开工：已提交 `2aaed62`；本文件为此后新增设计。

## 2. 已确认总体方案与实现约定

### 命名和页面

顶部入口叫“学习资料”，不叫资源：当前内容是用户主动整理出的私人材料，不是外部资源市场或公共资料库。

列表显示：标题、来源对话、科目、创建时间、生成状态、格式，以及预览／下载／失败后重试。资料标题由模型概括；任务刚创建时使用安全占位标题。

对话页顶部增加“整理学习资料”按钮。点击后立即创建异步任务，在当前对话追加文件卡片：

- 排队／生成中：显示状态，不让用户等待一个长 HTTP 请求。
- 已完成：显示标题、Markdown 标记、预览与下载。
- 失败：显示可理解的固定原因和人工重试入口，不把半截 Markdown 当成完成。

沿用现有布局、Arco 组件、主题和安全 Markdown 渲染，不增加字体或新 UI 依赖。

### 生成的材料

不是问答流水账，不输出“我／知序”等发言者分段，不复述寒暄、工具状态、请求 ID 或内部版本号。

按对话内容选择合适结构，不强迫没有例题的对话生成虚构例题：

1. 标题、主题与学习目标。
2. 核心知识点和概念关系。
3. 关键问题与整理后的解答。
4. 已讨论的例题：题干、选项、已核验答案、解析及易错点。
5. 易混概念、方法步骤、结论或公式。
6. 必要时给出复习清单；明确区分学习建议和官方要求。

删去重复讨论，合并同义解释，使用后续已经确认的纠正，不把用户猜测当成事实。依据不充分或有争议的结论明确标注待核实。考纲来源确有必要时简洁放在相关段落末或资料末尾，不在开头堆砌页码。

未作答题不能通过“整理资料”泄露隐藏答案。任务输入只包含用户已看到的内容与 Java 允许公开的已判分结果，不取完整内部题目快照绕过答前限制。模型不擅自编新题；没有例题则不加例题章节。

### 两种触发，共用一个任务入口

- 按钮明确触发，不经过普通聊天模型路由。
- 自然语言通过已有短结构化意图识别扩展为“生成学习资料”，由 Java 校验并执行。覆盖不同说法，不用几个关键词硬匹配，也不把引用、否定或询问功能本身当作执行命令。
- 用户指定主题／侧重点可作为整理要求；未指定则整理截至本次请求前的有效学习内容。
- 同一个会话同一时刻仅一个活动整理任务；另持久记录 user/session/requestId、参数哈希和 taskId，即使任务已经完成，旧请求重放也返回同一资料，不重复计费。相同请求键但参数不同返回冲突；人工重试使用新的 attempt／generation 隔离旧结果。
- 按钮和自然语言均进入同一任务创建服务；自然语言路由完成后直接返回任务状态，不再额外调用普通讲解来描述“已创建”。
- 支持日后再次整理，形成新的资料，不静默覆盖之前下载过的版本。

### 异步和保存

首版选择 PostgreSQL 持久保存 Markdown 正文及资料元数据，而不是每次下载重新生成，也不为了小型文本先增加对象存储依赖。下载由 Java 鉴权后按 UTF-8 输出 `.md` 文件，使用安全文件名和正确的 Content-Disposition。

资料是独立私人资源，绑定生成者和来源会话。删除来源对话不会连带删除已经生成的资料；资料列表仍可查看原来源标题，但不提供已删会话访问绕过。生成任务在创建时冻结用户可见的输入快照，因此新消息或会话删除不改变本次整理输入。

任务生命周期：queued → processing → ready／failed。使用真实 RocketMQ 投递／消费，不使用 PG 扫描来领取生成任务。API 在同一事务写资料任务、冻结快照和 mq_outbox；独立 Worker 以有界 Outbox relay 可靠投递消息并消费。MQ 消息只含 taskId／generation／eventId，不含私人上下文和模型凭据。

API 仍是业务写入唯一入口：Worker 经专用 HMAC 内部接口请求投递领取／确认及任务执行，不能直接写资料、任务或审计业务表。消费回调等待内部执行结果，页面创建任务立即返回。Java 执行接口以任务行锁、generation、租约保证至少一次投递下只领取一次；消息重复不会重复调用模型。Outbox 投递失败可以重试，不等于重试付费生成。重启后未开始任务依赖持久 MQ／Outbox 恢复；无法证明是否已计费的超时 processing 任务标为 failed，等待人工重试，不自动重复调用。后台只为租约过期维护扫描，不以数据库轮询替代 MQ 消费。资料排队超过30分钟仍未被消费时，维护将其标为failed，提示检查MQ后人工重试，避免消息进入死信后永远queued；重试创建新generation，旧死信消息不能恢复旧执行。不从维护扫描自动调用模型或自动重建付费任务。

本机 API、Worker、Python 分别运行；NAS 仅保留现有 MQ 等中间件，不部署应用。新的 Topic／Consumer Group、真实消息冒烟及新数据库迁移执行需要分别说明范围并授权。

对话删除只中断普通对话生成，不取消已经独立创建的资料整理任务；排队和生成中的整理任务继续使用创建时授权的冻结快照。文件卡片绑定 taskId，不能只存在临时 SSE 状态中，刷新后仍能由持久化任务状态恢复。

资料卡与对话消息独立持久关联，在 Java 会话公开视图中合成并按稳定创建位置展示；后台生成完成仅更新资料任务，不回写整份 state_json，避免被正常对话 checkpoint／finish 覆盖，也不依赖源会话仍未删除。冻结范围排除本次整理指令、文件卡和生成状态提示。

PDF 预留格式和生成器扩展边界，首版界面不展示不可用的 PDF 下载按钮。

### 大上下文预算

整理使用冻结的完整有效对话，不套用普通聊天最近 10 条／每条 6000 字的上下文裁剪规则；普通聊天限制不因此全局放开。

当前会话 state 只保留最近 100 条消息，不能把它等同于完整历史。资料快照读取器按已完成轮次顺序合并其公开 response_json 和当前已持久化消息，按消息 ID 去重、保留最新已判分版本及首次出现顺序；不能拼接每轮完整视图导致重复。以创建任务时的数据库一致性快照为截止点，不使用半截 SSE。未来需要长期完整消息归档时应独立持久保存公开消息，而不是单纯无限放大会话 JSON。对无法恢复的历史缺口必须明确提示，不能宣称覆盖整场对话。

资料保留必要的原题／公开判分与来源元数据快照，原文引用和 AI 归纳用清晰章节区分；源会话删除后禁用跳转，但已整理内容的必要出处仍可独立阅读，不只剩一个失效链接。

用户确认项目全部 LLM 为 1M 上下文。首版任务输入默认上限为有效内容 100 万字符、序列化快照 8 MiB，均可配置；正文输出独立配置（最多 32768 output tokens，Markdown 上限 10 万字符）。这些是本地资源预算，不等于 token 数。1M 是模型输入输出整体窗口，仍需给系统提示、元数据和输出留空间，不能声称 100 万字符一定等于 100 万 token。

超过预算明确说明，允许用户缩小范围；不悄悄只取最后几轮，不用无提示截断伪装成整理整场对话。预留之后按主题分段整理再合并的扩展，但首版不因超限自动产生多次付费调用。

后台整理采用独立可配置超时并统一 Java 后台任务、Java→Python HTTP、Python→Provider 各层预算，避免再次出现模型允许 180 秒而 Future 在 110 秒先中断。长生成不占普通对话 SSE 并发名额，最多少量并行任务；输出截断时标记失败，不发布残缺资料。

### 安全和审计

浏览器全部经过 Java；Python 仅通过内部 HMAC 接受冻结上下文并返回结果，不直接写业务资料表。

资料列表、详情、状态、下载、重试都按 user_id 过滤；Admin 无权查看个人学习资料，无法通过来源会话关联越权。材料正文、来源和整理要求视为不可信数据，不能执行其中的提示词指令。

每次真实模型整理调用纳入现有 AI 审计，记录独立业务类型和成功／失败状态。资料调用的请求／响应审计只保存结构元数据、大小、快照／正文摘要、错误类别，不把整份私人快照或 Markdown 写入 Admin 可读的 exchange；现有普通陪练审计规则不在本次顺便改造。资料正文与冻结快照仅由本人业务接口读取。用户正文不打入普通日志，不输出密钥。任务状态和文件卡片来自 Java 权威结果，不采信模型声称“文件已保存”。

## 3. 数据库与交付边界

需要新增资料／生成任务持久化结构及最小权限；迁移编号按实际下一版本确定，不能更改已经执行的 V12。编写与本地测试迁移不等于获得群晖执行授权，执行前需另行说明并征得用户明确同意。

验收覆盖：两种触发、只创建一次任务、异步状态、模型提炼而非原样导出、前端文件卡、跨对话资料汇总、Markdown 下载、失败重试、长上下文与超限提示、未答题防泄露、跨用户／Admin 拒绝、删除来源会话后资料独立保留、重启／超时不自动重复计费。

真实模型验收使用用户允许范围内的数据并明确说明调用；真实数据库迁移与业务数据操作单独授权，不使用静态测试宣称真实环境已经上线。
