# 私人题目池与 Agent 对话式导入设计

日期：2026-11-09。

状态：用户已确认产品方向，本文记录需求与推荐边界；尚未实现，不代表已完成技术接线或真实环境验收。本文不授权新增数据库迁移执行、共享资源写入或部署，不自动安排进本周交付。

## 1. 需求与目标

用户在个人 Agent 页面上传文本、文字型／扫描 PDF、截图或照片，然后说：

> 帮我导入到我的题库中。

Agent 自动处理材料、检查题目并存入本人题目池。正常内容直接通过，不逐题确认、不跳后台审批；存在疑点时，Agent 在聊天中提出建议，由用户通过问答决定如何处理。

核心原则：

1. **一个人一套私人题目池，不按试卷分库，不要求创建多个题库。**
2. **聊天是主要操作入口，结构化管理页只是用户侧辅助入口。**
3. **正常题自动入库并可练习；有问题的题单独处理，不阻塞其他题。**
4. **建议、澄清和确认都在对话中完成，不强制切换页面。**
5. **保留来源和可纠正性，不将 AI 自检等同于答案已被证明正确。**

## 2. 与历史方案的关系

本文覆盖旧私有题库计划中以下产品设定：

- “普通用户创建多个私库”改为“每位用户一个题目池”。
- “按试卷组织私人题目”改为“科目、知识点等标签组织，来源文件仅作为来源信息”。
- “每题生成草稿后必须人工确认”改为“低疑点内容自动通过，仅疑点内容交互处理”。
- “管理页承载必经的核对确认”改为“聊天内完成，管理页可选”。

公共题库不受本次调整影响：平台公共内容仍走原有审核发布流程，后台一个题库对应一份试卷的约定继续有效。

保留历史方案的用户归属与隔离要求；不得把公共内容权限复制成私人内容的全局访问权限。

参考：[历史私有题库计划](../plans/2026-11-07-private-question-banks.md)、[多来源证据层设计](../../多来源导入证据层设计.md)。

## 3. 用户体验

### 3.1 上传并开始

1. 用户在 Agent 输入区添加附件，或粘贴原文。
2. 用户发出明确指令，例如“帮我导入到我的题库”。
3. 这条指令就是对本批次新增导入的授权，不再重复弹出“是否确认导入”。
4. 只有缺少会实质影响导入的信息时才追问，例如混合科目无法判断。可沿用当前科目作为初始上下文，但不能明知混科仍全部强行归类。

不能仅因用户上传了附件就立即开始付费解析或写入；用户也可能只是想咨询文件内容。附件正文不得被当成用户授权指令。

### 3.2 自动处理与进度

聊天中展示实际阶段与结果：

- 文件预检；
- 文字提取／按需 OCR；
- 候选题识别与图文关联；
- 结构、一致性和重复检查；
- 自动入库与疑点汇总。

进度必须有任务状态依据，不伪造百分比。批量处理采用持久化任务，离开页面或 SSE 断开不应丢掉任务。重新打开对话可以继续查看进度和处理结果，不自动重发整个导入。

### 3.3 正常题直接通过

能完整识别题干、选项、原答案，且没有发现缺图、明显冲突或边界异常的题，可以自动存入并进入可练习状态。

导入结束由 Agent 汇报：自动入库多少题、跳过多少明确重复题、多少题仍有问题，以及下一步可选动作。数量必须来源于任务结果，不由模型猜测。

“自动通过”不等于后台审核认证，更不等于知识事实绝对正确；用户随时可通过聊天或题目详情纠正。

### 3.4 疑点在聊天里解决

示例仅描述交互形式，不代表实际导入数量：

> 已导入 26 道题，还有 3 道需要处理。第 8 题原答案与解析冲突，第 15 题图片不清，第 21 题没有标准答案。我们先看第 8 题？

用户可直接回答：

- “按原答案保留。”
- “第 15 题先跳过。”
- “缺答案的你补一下。”
- “这些先存着，不拿来刷。”

Agent 展示必要的原文、题卡或原页局部，提出具体建议并执行用户选择；不要求打开管理页。

相同类型疑点可合并询问，避免一次问几十遍。批量答复必须绑定本次任务及明确的一组题，不能当成未来任意导入或修改的永久授权。含糊答复先澄清，不能扩大解释为全量覆盖。

## 4. 题目池组织

- 归属以服务端认证用户为准，不接受前端自报 owner 作为授权依据。
- 用户不用创建或选择试卷容器。
- 题目可按科目、知识点、难度、来源等筛选；科目分类仍保留，不能无意间把不同考试方向混在一起练。
- 保留文件、导入批次、原题号、页码／图片证据等来源关联，但这些不形成独立私人试卷库。
- 同一知识点练习可以跨本人导入文件；不得跨用户召回私人题目。
- 后续公共与私人题目混合练习时，应明确来源和选择范围；具体默认范围另行设计，本次不擅自决定。

## 5. 输入与解析策略

| 输入 | 目标处理方式 | 关键限制 |
| --- | --- | --- |
| 粘贴文本 | 识别题目边界、选项、原答案和解析 | 不把旁注或个人作答当标准答案 |
| 文字型 PDF | 提取正文、页码和题号 | 处理跨页，不能按当前样本硬编码 |
| 扫描 PDF | 按需逐页 OCR，结合版面识别题目 | 模糊、旋转和多栏可能需要追问或重传 |
| 截图／照片 | OCR／视觉识别，分离 UI 和题目 | 排除按钮、头像、个人勾选等噪声 |
| 图文混合题 | 保存题图与正文关联 | 不得丢图后伪装成完整文字题 |

沿用当前阶段只做单选、多选的范围；综应／申论等主观题不因本次多来源导入而自动纳入。

文件类型、大小、页数、OCR及模型调用预算应在实施时设上限；超限先说明可选方案，不无限自动处理。

## 6. 自动通过与疑点规则

下列为推荐默认行为，具体阈值和识别规则须实现并用测试证明，不只靠模型一句“高置信度”。

| 情况 | 默认处理 |
| --- | --- |
| 题干、选项及原答案完整，没有发现明显冲突 | 自动入库、可练习；保留来源 |
| 缺标准答案，AI给出建议答案 | 保存并标注AI来源，在聊天中说明；用户明确允许该批采用建议答案后可用于练习 |
| 原答案与原解析／模型检查冲突 | 不静默改写，聊天给出差异和建议 |
| 缺选项、缺图、边界不清、图片模糊 | 保存待处理内容，暂不正常抽题，聊天建议补充或跳过 |
| 明确重复 | 不重复增加题目，保留本次来源关联或跳过结果 |
| 疑似重复但存在答案／版本差异 | 提示差异，不静默覆盖已有题 |
| 用户要求“先存着，不拿来刷” | 保留题目与疑点，排除出题范围 |

不设计公共内容式“草稿—确认—发布”审批链；实现仍需要可追踪的内部状态，以区分处理中、可练习、待处理及排除项。状态名与表结构留到技术计划确定。

用户已明确希望减少确认。此处仅对关键缺失或答案来源变化提出问题，不将所有题重新变成逐题审核。

## 7. 内容与答案的可信度

- 原答案／原解析优先保留，不因模型意见而静默替换。
- 模型补全、修正或推断需要保留来源标记，与原材料事实区分。
- 知识检索结果保留出处和适用时间，冲突不能宣称已核验。
- 不以模型自报confidence或一次自检，作为答案一定正确的证明。
- Java根据保存的答案判分，表示用户选择是否匹配该答案，不证明该答案本身必然正确。
- 支持后续纠错，必要时保存版本关联，使既有作答不被新答案悄悄改写。

## 8. 用户侧简化管理页

管理页是普通用户的“我的题库”，不是Admin后台，也不是导入的必经步骤。

最小功能：

- 搜索题目，按科目、知识点和处理状态筛选；
- 查看题目、来源与原页；
- 修改、删除、排除练习或恢复练习；
- 查看仍待解决的疑点，并可回到聊天继续处理。

不增加多个题库／试卷层级、强制建库流程或管理员审批界面。复杂编辑可作为用户自选辅助方式，但提建议与确认始终支持问答。

## 9. Agent 工具与任务边界

建议将能力组织成“私人题目导入”模块，后续可登记为应用级Skill，但不能仅凭文档就声称已实现Skill／ReAct。

建议的受控能力包括：

1. 获取当前用户可访问的附件；
2. 文件预检与文本提取；
3. OCR／视觉处理；
4. 候选题抽取与证据关联；
5. 结构校验、冲突与重复检查；
6. 批量写入本人题目池；
7. 汇总疑点、接收聊天决策、恢复任务；
8. 查询实际结果并反馈。

具体工具名、schema和API在技术设计时确定。确定性步骤可由代码工作流控制；模型根据观察选择工具时才属于模型驱动Tool Use／ReAct，仍应有步数、时间、费用和权限限制。MCP不是该功能的前置条件。

## 10. 安全、授权与可恢复性

- 用户一句明确导入指令授权本批新增，不代表授权删除、覆盖旧题、公开分享或不限量外发检索。
- 普通新增无需二次确认；批量删除、覆盖已有内容等难恢复操作仍须在聊天中明确确认。
- 自动化处理可调用已配置模型，但必须明确附件可能发送到外部OCR／模型供应商；“私有”表示平台内归属隔离，不等于内容始终不离开本机。
- 不默认把私人原文或图片发送到公开搜索服务，检索外发边界在实施时明确。
- 隔离覆盖数据库查询与关联、工具、缓存、向量索引、MQ事件、附件授权、导出及统计，不能只隐藏菜单。
- Admin不因此获得私人题目CRUD或会话浏览权限；已授权AI审计属于独立访问边界，私人导入的审计字段与原文范围须明确，不默认为任意扩权。
- Java是业务写入及身份事实源；Python不直接写私人业务题表。
- 上传、任务开始、候选写入和聊天决策需要幂等，断网恢复不能重复插入或自动重复计费。
- 每道题独立记录结果，单题失败不回滚已经正确导入的其他题。失败／取消后的资源与任务状态可恢复，不能靠长连接保存全部进度。

## 11. 验收清单

- [ ] 上传PDF并说“导入我的题库”，无需建库、选试卷或重复确认即可开始。
- [ ] 正常题自动可练习；疑点题不阻塞其他题，不逐题强制确认。
- [ ] 文本、文字PDF、扫描PDF、截图处理路径明确；不支持的情况如实说明。
- [ ] 跨页、缺图、个人勾选、原答案冲突可识别或进入待处理，不假装完整。
- [ ] 聊天能查看证据、提出建议并执行逐题或范围明确的批量决策。
- [ ] 未答复疑点不会自行扩大授权；模型补答案明确标记，不冒充原标准答案。
- [ ] 一人一套题目池，可跨文件按科目／知识点练习，无强制试卷层级。
- [ ] 管理页属于用户侧且可跳过，聊天覆盖全部核心维护流程。
- [ ] A用户不能读取或修改B的题目、附件、任务、索引与决策；Admin普通内容接口同样不可越权。
- [ ] 重复请求、断流、离开页面和任务恢复不重复导入，不自动重放付费操作。
- [ ] 测试先用本地替身，真实OCR／模型／PG／附件链路单独记录证据，不将本地通过写成真实验收完成。

## 12. 实施前需细化的技术事项

不改变已确认产品方向，后续技术计划还需落实：

- 私人题目、版本、附件、任务与疑点决策的表结构及迁移影响；
- 自动通过条件、重复判断规则、AI答案标记及练习准入规则；
- OCR及视觉能力选择、资源限制与成本预算；
- 聊天内附件／疑点卡片协议，批量决策作用范围及任务恢复方式；
- 删除、覆盖、纠错对既有作答快照的影响；
- 私人索引权限、审计范围和公开资料检索外发策略。

上述事项不预先锁定具体实现，也不在生成本文时执行迁移或修改业务代码。
