# 模型服务本地验证方法

更新：2026-11-11。实现事实依据当前源码、依赖清单和测试核对；不以旧文档推定运行状态。

这是当前验证方法，不沿用旧报告宣称供应商仍可用。本轮整理没有发真实付费请求。

Python配置由`Settings`读取环境，脚本显式加载自身.env；TEXT_LLM_BASE_URL/API_KEY/MODEL任一出现即采用整组，不能混用旧组补值。普通文本模型使用OpenAI-compatible Chat Completions；OCR、Embedding、Search、Fetch各有独立基地址/密钥，缺配置不借用其他密钥。

只读检查Python`GET /health/live`仅证明进程。真正模型验证应使用合成短问题，检查请求是否仅调用一次、输出契约、stop/[DONE]、max_tokens与超时；不要用真实题库/私人会话做无目的连通性测试。

Tool Use默认开启：纯答疑可要求检索公开资料并读取一篇来源，检查参数分片、tool角色回传、tools不支持时一次降级、网络错误不自动重试、来源刷新与审计。Search可单独配置，Fetch亦可单独配置；recency=year目前明确不支持。

Embedding需核实实际返回模型/维度、有限非零向量；不能由模型名猜维度或强行沿用旧1024维。OCR只验证独立适配器不等于图片导入已接线。Fetch经第三方服务，本地校验不能代替其内部每跳公网限制。供方行为或价格会变化，实际测试结果只记录日期和合成请求，不回显凭据。
