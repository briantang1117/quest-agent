# PC 个人中心与 AI 陪练：联调与验收

## 本轮范围

用户明确：后台先到这里，下一步做**基于 AI 的交互式刷题**，不做传统“选试卷—做题—交卷”；刷题端只确定科目、不被卷子限定；移动端暂不考虑。已实现 PC 端个人中心单选科目 → 学习空间快捷入口 → 个人 Agent 对话一题一答、判定、讲解、继续下一题。

**一个题库=一份真题试卷只约束后台**。个人 Agent 按用户当前科目，从该科目下所有题库的**已发布、未删除**题目中选题，跨试卷，不生成新题。用户允许调用文本 LLM；首版不调用 OCR、Embedding、联网检索。

## 用户流程

1. **个人中心** `/practice/profile`：单选“事业编 A 类 · 职测 / 上海市考 · 行测”，保存到后端。未选择时学习空间不创建会话。
2. **学习空间** `/practice`：显示当前科目，提供“开始互动刷题”“和个人 Agent 聊聊”“继续上次对话”。不需要选试卷。
3. **个人 Agent** `/practice/agent`：
   - 从快捷入口进入时由服务端一次性创建会话并给出第一题；**首句不是每次刷新重发的**，刷新只读取会话。
   - 题目以卡片展示，单选/多选可点选，也可在输入框说思路或追问。
   - 提交后由 Java 判定正误，展示你的答案、正确答案、解析，再由 LLM 结合权威判分解说；讲解失败不影响已保存的作答。
   - “继续下一题”由 Java 选题，不重复已出过的题；本会话练完会明确说明。
   - 侧栏显示我的对话，可切换继续。

## 安全与正确性边界

- 只有 `student` 会话可访问；Admin 调用返回 403。会话、消息、作答全部绑定当前用户；他人会话 ID 返回 404，不区分“存在但无权限”。
- **答前不下发答案、解析、原始来源**。前端只拿到题干、题型和选项。
- 判分在 Java 用题目快照做集合比较（多选全对才算对），LLM 只能解释，不能修改判分或替用户提交。
- 用户说“选 B”等明确提交时，卡片仍需确认；含糊表述（“为什么不选 A”）先澄清。
- `requestId` 幂等：同一请求重复提交返回首次结果，不重复计分、不重复调用模型；处理中或状态已变化返回 409。
- 会话创建 UUID 作幂等键，重复创建返回同一会话。
- 换科目只影响**新建会话**；旧会话保留原科目，不会串题。
- PC 统一流式轮次无自动重试、无工具自治；兼容旧同步接口保留原结构校验的有界重试，不影响新的流式链路。
- PC 使用一次 `POST /api/v1/coach/sessions/{id}/turns/stream`。点击提交答案由 Java 直接判分，模型只生成一次正文；自由输入先用短结构化路由识别意图，再按需生成正文。
- JSON 与 SSE 不冲突：Python 从模型 JSON 流中增量提取顶层 `reply`，前端只收到正文 `delta`。完整 JSON、结束原因与 `[DONE]` 全部校验后才返回建议；Java 将完整消息与建议落库后才发送 `done`。
- `state` 提前返回已保存的用户消息／判分，`delta` 临时展示，`reset` 放弃半截正文，`done` 替换权威会话。断流不自动重发付费请求，前端只读恢复状态；已保存判分不回滚。
- 生成入口最多 8 个并发且会话互斥，整体截止 140 秒，上游正文截止 95 秒。超过 5 分钟的遗留认领在下一次请求时标记失败并释放，不自动重放；所有善后更新必须匹配原用户、会话和 requestId。
