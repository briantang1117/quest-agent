# 用户模块：本机验证、V4与首个 Admin 初始化

本轮只实现 API 用户业务，不实现私有题库、内容/用量统计和 Refresh Token。不代表当前 NAS/IDE 服务已升级；未运行任何远端迁移或创建真实账号。全部测试采用隔离 H2，未读取真实连接配置。

## API 与权限

契约遵循 `docs/superpowers/plans/2026-11-07-user-module.md`（仓库根）。统一 `{code,message,data,traceId}`，UserProfile 的 id 为 JSON 字符串，时间为 UTC ISO-8601。

- `POST /api/v1/auth/login`：真实 bcrypt 验证，返回 2h HS256 JWT 和 UserProfile。
- `GET /api/v1/auth/me`、`POST /api/v1/auth/logout`、`POST /api/v1/auth/change-password`。
- `GET/POST /api/v1/admin/users`、`PATCH /api/v1/admin/users/{id}/status`、`POST /api/v1/admin/users/{id}/reset-password`，只管理 student 元数据。
- 不提供注册、删除用户、创建 Admin 或 HTTP bootstrap；不返回假统计。
- 创建/重置后强制改密；仅 me/logout/change-password 可用。新口令不得等于旧口令。
- Admin 只开放上述本人认证、用户元数据和 system/info；其他内容或未知业务路径默认拒绝，包括未来 practice/papers/attempts/analysis/agent/私有题库端点。Student 不能访问任何 `/api/v1/admin/**`。
- JWT role/scope/authorities 不参与授权；数据库 account_type 决定互斥角色。每次请求核验 active、must_change_password 和 sid 对应的未撤销、未到期数据库会话，不提供无 sid 兼容后门。
- 登出只撤销当前会话；改密/重置撤销全部旧会话，改密返回新会话；禁用撤销所有会话，再启用不恢复旧 token。
- JDBC 事务加用户 `FOR UPDATE` 锁序列化登录/重置/禁用/改密，后台操作重新验证操作者会话。审计仅含 actor/action/target/trace，不记录 hash、明文或 token。

密码 12–64 Unicode 字符且 UTF-8 <=72 字节，不 trim；用户名 `[a-z][a-z0-9_]{2,31}`；展示名 strip 后 1–64 字符。分页 page>=1、size1–100，keyword 最多128字符并将 LIKE 通配符作为字面量匹配。HTTP 错误码采用计划约定，数据库不可用为 50300，不回退假内存账号/无状态鉴权。

## 登录限流边界

默认单进程固定15分钟窗口，账号10次、来源IP60次，**所有尝试包含成功登录均计数**。两个 map 各最多10000项，容量耗尽拒绝新 key，窗口到期清理，不驱逐活跃 key 让攻击者绕过。未知账号/错密码/禁用使用相同401文案；异常返回503，不吞成错密码。

默认来源只采用 servlet remoteAddr，不信任自报 X-Forwarded-For；`server.forward-headers-strategy=none` 防止容器提前改写 remoteAddr。可通过 `quest.security.login.trusted-proxies` 配置逗号分隔、精确 IP 字面量白名单（默认空），只接受白名单直连代理**覆盖**的单值 `X-Quest-Client-IP` 字面量；缺失/多值/列表/主机名拒绝400，不进行DNS查询。不要把不受控局域网/互联网地址列为代理，不配置CIDR通配。

启用前代理必须剥除浏览器提供的同名头并用实际socket来源覆盖，例如Nginx `proxy_set_header X-Quest-Client-IP $remote_addr;`；Vite代理需由可信开发配置在proxyReq事件以请求socket.remoteAddress覆盖，不能透传浏览器同名头。API端口必须只允许这些代理连接；同机不可信进程仍可能冒充127.0.0.1代理，开启前需评估部署信任边界。集成方已协同在PC/mobile Vite与部署Nginx覆盖专用来源头，后端默认仍不自动信任loopback，真实.env未修改；在用户显式配置可信代理之前，Vite/Nginx代理仍共享60次/15分钟来源窗口。这是保守限制，不以放宽阈值规避，生产上线前需显式配置并验收覆盖头。正式多副本/跨进程重启还需Redis共享限流。当前重启会清空窗口，不是分布式防护。限制可用 `quest.security.login.account-limit`、`source-limit` 配置，须为正整数；不要公开放大或关闭限制。已受限来源立即拒绝，不再污染账号窗口容量。

## 测试与日常运行

从仓库根运行项目 wrapper（固定公共源及项目JDK27）：

```bash
./backend/mvnw -B -ntp test
./backend/mvnw -B -ntp package
```

测试显式关闭配置文件导入、Flyway，以 H2 PG mode 执行 V4 表结构/历史数据变更和真实 JDBC 事务，经 MockMvc 验证完整 bearer 安全链，不是全 mock。H2 不支持 PG 的 sequence GRANT，只在测试装载器剔除此条并断言其存在；PostgreSQL 权限及 advisory 锁行为仍须后续获批后真实验证。bootstrap 测试用本机 H2 函数替身模拟 PG advisory 锁，不代表已验证 PG 跨进程锁。

现有 ApiContractTest 已迁至隔离 H2 会话，不为旧测试开放无 sid JWT。旧 demoLoginDoesNotExist 改为仅 POST 登录匿名/坏 JSON 契约，真实登录成功失败由 UserModuleTest 覆盖。local 无数据库保持健康可用、业务拒绝503；匿名业务依旧401。deployment 密钥必需、禁止与 local 混用，日常 Flyway 默认关闭。

## 后续获批后安全迁移（本轮不执行）

1. 先申请单独的 NAS V4 授权，核对备份、V1–V3历史及校验和、已有用户和旧角色。禁止重建库或修改旧迁移。
2. V4 位于 `src/main/resources/db/migration/V4__user_accounts_and_sessions.sql`。部署兼容副本由集成方同步，需校验两文件逐字一致。本 Java 工作范围没有修改 deploy。
3. **V4 会禁用全部历史 app_user，统一默认 account_type=student、must_change_password=true。旧 super_admin/其他角色不自动升 Admin，旧角色关系不再授权。**这会影响所有历史账号，必须逐项审查并获得用户对该影响的明确批准；不能直接靠旧角色叠加权限恢复账号。历史用户名/哈希如不满足新规则需人工审查，不公开放宽校验。
4. 使用隔离迁移会话和 quest_owner，仅显式执行已批准 V4。日常 API/IDE 和 Worker 继续关闭 Flyway；不要给运行进程 owner 凭据。不运行历史 migrate.py。
5. V4 显式给 quest_app `auth_session` SELECT/INSERT/UPDATE 和既有 app_user/audit_log 序列 USAGE/SELECT（UUID 会话无新增序列）；quest_ai 明确 REVOKE app_user/auth_session，PUBLIC 不可访问 auth_session。验证角色不通过继承其他角色获得额外访问，运行账号不能修改审计历史。
6. 验证 PG 事务/权限、历史账号 disabled、所有会话均需 DB、没有内容/统计扩权。会话/审计持续增长，生产后续需要独立保留/归档政策；本轮没有自动删历史数据。
7. 如需回滚先停止新写入并采用已审批的备份恢复/前向修复方案，不能随意 DROP 表/清库。确认升级完毕再初始化首个 Admin，最后由用户自行重启 IDE 服务验收。

## 独立非 Web 首个 Admin 工具（默认关闭）

主类 `com.quest.api.auth.AdminBootstrap`，不是 Spring Bean/runner，不随 API 启动。它不加载 Spring、不导入 `.env.api.properties`、不启动 HTTP、不执行 Flyway，只连接操作人独立指定的 PostgreSQL。不要在 NAS V4 未获批前运行。

工具强制显式开启与确认、交互终端、独立 `quest_owner` 迁移账号（不接受 quest_app）、无命令行秘密。数据库和 Admin 口令由 Console.readPassword 不回显输入，不打印连接参数/异常堆栈/凭据。JVM/JDBC 内部 String 不能保证密码内存可零化；交互 char[] 会清零，不把口令放 shell history、环境或日志。

先完成本机 package，然后在可信终端独立、短期操作环境设置非秘密项，URL/用户名应由操作人核验，以下不是现有真实配置：

```bash
export QUEST_ADMIN_BOOTSTRAP_ENABLED=true
export QUEST_ADMIN_BOOTSTRAP_CONFIRM=CREATE_FIRST_ADMIN
export QUEST_BOOTSTRAP_JDBC_URL='jdbc:postgresql://<approved-host>:<port>/<database>'
export QUEST_BOOTSTRAP_DB_USER=quest_owner
./backend/tools/jdk/Contents/Home/bin/java \
  -Dloader.main=com.quest.api.auth.AdminBootstrap \
  -cp backend/api-java/target/api-java-0.1.0.jar \
  org.springframework.boot.loader.launch.PropertiesLauncher
unset QUEST_ADMIN_BOOTSTRAP_ENABLED QUEST_ADMIN_BOOTSTRAP_CONFIRM QUEST_BOOTSTRAP_JDBC_URL QUEST_BOOTSTRAP_DB_USER
```

在同一事务中获取固定 PostgreSQL `pg_advisory_xact_lock`，检查任何状态的 account_type=admin 数量必须为0，再插入唯一首个 active Admin 和安全审计。多进程工具遵守同一事务锁，不以“先查再无锁写入”初始化。若存在 disabled Admin 也拒绝，不提供覆盖/重置后门。首次 Admin 由操作人自行选择强口令，mustChangePassword=false（不是分发给 student 的初始密码）。已有账号不自动转换成 Admin；后续额外 Admin/恢复程序需要另行安全设计与授权。

成功只输出完成提示，失败只输出脱敏拒绝消息、退出码1。首次创建后立即撤下临时 owner 环境，API运行继续使用quest_app。此命令在本轮只验证默认关闭路径，没有连接NAS或创建真实Admin。
