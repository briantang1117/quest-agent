## 已实现接口

基础路径 `/api/v1`：

| 方法       | 路径                               | 用途                    |
| ---------- | ---------------------------------- | ----------------------- |
| POST       | `/auth/login`                      | 用户名和密码登录        |
| GET        | `/auth/me`                         | 当前身份                |
| POST       | `/auth/logout`                     | 退出并使会话失效        |
| POST       | `/auth/change-password`            | 修改密码                |
| GET / POST | `/admin/users`                     | 管理员分页查询/创建用户 |
| PATCH      | `/admin/users/{id}/status`         | 修改用户状态            |
| POST       | `/admin/users/{id}/reset-password` | 管理员重置密码          |

UserService 使用 PostgreSQL、BCrypt 和服务端会话状态；JWT 使用 HS256，校验签名、issuer、audience、expiry 和 subject。SessionSecurityFilter 再核验服务端会话及用户状态，改密、重置和禁用涉及会话失效。业务层校验 admin/student 权限及强制改密状态。没有开放注册接口。

登录限流由 LoginLimiter 在进程内按账号和来源维护，默认账号10、来源60。LoginSource 仅信任显式配置的代理白名单；容器禁用自动转发头改写。进程内限流不等于多实例共享 Redis 限流。

## 首位管理员

`com.quest.api.auth.AdminBootstrap` 为独立交互命令，不随 API 启动运行，也不读取应用 .env。要求终端交互，禁止命令行携带凭据；通过 `QUEST_ADMIN_BOOTSTRAP_ENABLED=true`、`QUEST_ADMIN_BOOTSTRAP_CONFIRM=CREATE_FIRST_ADMIN` 显式启用，连接由 `QUEST_BOOTSTRAP_JDBC_URL` 和 `QUEST_BOOTSTRAP_DB_USER=quest_owner` 提供。口令通过不回显提示输入。

需先具备 V4 数据结构。命令在事务内获取 PostgreSQL advisory lock，只在不存在任何 admin 时创建首位管理员，并写 audit_log。已存在管理员会拒绝。后续用户维护通过管理员接口完成。本次没有执行初始化或数据库迁移。

## 其他安全入口

普通内部路径默认拒绝；资料的三个精确 POST 由 MaterialInternalFilter 校验服务 token、HMAC、时间戳、nonce 和原始请求体。陪练新增精确 `/internal/coach/workflow-step`，使用独立过滤器并额外验证Java签发的短期轮次授权、原登录/归属/处理中轮次；详见[编排技术说明](../../../docs/做题Agent编排技术说明.md)。AI 请求经 PublicAiClient 签名，AI 调用元数据记录 audit_log，原始请求/响应记录 ai_call_exchange，管理员通过 `/api/v1/admin/ai-calls` 查询。编排授权字段在审计前移除，其他业务原文仍可能存在数据库中，后续应核验留存和访问规则；不能宣称全部审计已自动脱敏或日志从不含业务原文。
