# PC 页面单向缓存

更新日期：2026-11-11。工程入口见[根 README](../../README.md)，功能范围见[项目现状](../../docs/项目现状.md)，服务边界见[架构说明](../../docs/架构说明.md)，启动见[本地开发启动](../../docs/本地开发启动.md)。

## 路由配置

在业务路由的 `meta` 中设置 `pageDeepth`（沿用参考项目字段拼写）：

```ts
meta: { title: '列表', pageDeepth: 1 }
meta: { title: '详情', pageDeepth: 2 }
meta: { title: '编辑', pageDeepth: 3 }
```

沿用旧项目的 `mitt` 路由事件与 `KeepAlive include`。AdminLayout 与 PracticeLayout 使用统一 `DepthRouterView`，router 在成功导航后发事件，出口订阅并在卸载时退订。路由 `name` 必须与页面组件名一致；当前 Vue SFC 使用文件名自动推导组件名，例如路由 `name: 'AdminUsersView'` 对应 `AdminUsersView.vue`。登录、改密、诊断、404 不缓存。

## 缓存规则

- 浅层进入深层保留浅层页面的组件实例、筛选条件、分页与内存数据。
- 返回已保留的浅层页面时恢复该实例，并销毁更深层实例；再次进入深层重新创建。
- 同层切换销毁旧页面；同一组件不同参数、query、hash 默认以完整地址区分，旧同层实例不保留。例外是路由 `meta.transientQueryKeys`：从页面键移除一次性 query；当前 Agent 的 `prompt` 被忽略，消费提示词不会销毁正在处理请求的实例，`session` 仍参与页面身份。
- 未配置有效正数深度的页面不缓存，并清除该布局的访问链。
- 只有成功导航才更新缓存；取消、失败的导航不修改访问链。
- 使用 Vue 原生 KeepAlive，不包装业务组件、不注入路由快照；缓存页面的 `useRoute()` 仍是全局当前路由。后续给深层页面增加下钻导航时，页面自己的路由 watch/副作用需考虑停用状态。
- `bindInstance` 在渲染完成后同步业务实例，避免淘汰旧缓存时清空 Vue Router 的实例关联，确保恢复页面后的 `beforeRouteLeave` 仍能拦截导航。
- 缓存仅存在于当前布局内存，不写 localStorage；退出布局、账号/会话/角色/启停状态/强制改密状态或 API 地址变化会销毁原缓存。

## 滚动位置

按用户指定使用 Vue Router 标准 `scrollBehavior`：有 `savedPosition` 原样返回，没有则 `{ top: 0 }`。

浏览器前进/后退恢复历史位置；普通 `router.push` 返回列表回到顶部，即使列表组件状态来自缓存。未额外实现自定义滚动存储，不处理独立滚动 div；当前业务内容使用文档滚动。

## 源码与验证

实现入口为 `pc-web/src/components/DepthRouterView.vue`、`utils/route-listener.ts`、`composables/cache-scope.ts` 和 `router/index.ts`；两个布局通过缓存作用域作为出口 key 隔离身份。

`pnpm --filter @quest/pc-web test src/tests/route-cache.test.ts src/tests/route-listener.test.ts` 覆盖三级往返、同层切换、参数/query、浏览器 back、取消/重定向、实例卸载、离开守卫、身份作用域、滚动配置及 mitt 事件退订/实例隔离。

测试使用 jsdom，验证组件生命周期和滚动策略的返回值，不代表真实浏览器中的像素级滚动验收。
