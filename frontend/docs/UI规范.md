# 知序 UI 规范与本轮调整总结

更新：2026-11-07。用途：后续前端页面复用、跨会话交接和界面验收。记录用户最终选择，**被后续意见替换的初稿不再作为规范**。

参考项目为用户自建 `super-order-admin`，重点参考其 `EvaluationManagement`、`TablePageLayout`、`FilterBox`、navbar/menu/footer及编辑Modal。参考的是布局秩序和交互，不复制其业务逻辑，不照搬其蓝色品牌色。参考项目没有被修改。

## 1. 总体方向

- Admin是内部管理后台：紧凑、规整、克制，以表格和操作为中心，不做宣传页。
- **Admin与普通用户可以使用不同布局**。后台外壳独立，不能为了复用把学习页和管理页硬套一套导航。
- 文案服务于任务，不反复解释权限设计、内部架构和开发细节；安全隔离落实在系统中，不依靠长段页面声明。
- 只展示已实现功能，不添加空菜单、假统计、演示账号或假内容。
- 延续当前青绿色品牌，不随页面临时更换主色。

## 2. Admin 导航与页面外壳

### 层级

```text
58px Navbar：品牌文字 | 一级大菜单（系统管理） | 头像下拉
                    ↓
左侧：二级用户管理
       └── 三级用户列表
                    ↓
右侧：面包屑 → 全宽页面卡片 → 40px Footer
```

- Navbar承载**一级大菜单**，不是在顶部再重复放具体页面入口。
- 左侧承载二级分组/三级页面。
- **顶部一级菜单不放图标；左侧三级菜单不放图标；二级分组可保留图标。**
- 选中/展开跟随当前页面，现有单页使用固定keys；新增多个路由时应统一为路由驱动，不能复制固定users keys到其他页面。
- 保留现有权限守卫，改变导航外观不能让Admin进入学习或普通用户进入后台。

### 尺寸和位置

| 项           | 规范                                                 |
| ------------ | ---------------------------------------------------- |
| 顶栏         | 58px，固定顶部                                       |
| 侧栏         | 展开220px / 收起48px，顶端避开58px顶栏               |
| 内容区       | 占满剩余宽度，`min-width: 0`，无1300px等最大宽度限制 |
| 页面横向间距 | 16px                                                 |
| 卡片header   | 16px 20px                                            |
| 卡片body     | 0 20px 16px                                          |
| Footer       | 40px高、内容区内水平垂直居中、正常文档流             |

顶栏和侧栏固定时，内容必须同步让位；Footer不能fixed压住表格。不要在整个页面底部拉一条两端分散的大横栏，也不要把Footer塞到侧栏里。

### 侧栏折叠

- 使用Arco `IconMenuFold` / `IconMenuUnfold`。
- **不用 `«` / `»` 字符箭头，不显示“收起菜单”文字**。
- 保留`title`、`aria-label`和`aria-expanded`，图标按钮仍可被键盘和读屏识别。
- 不为“看着像完整后台”增加没有实际路由的菜单。
- 响应式断点700px：初始窄屏或从桌面缩至<=700px时，真正设置Arco collapsed=true，并由同一个状态同步48px宽度、内容偏移、折叠图标/aria；**禁止媒体查询单独把侧栏压窄而组件仍展开**。
- 窄屏允许手动展开为完整220px，同一断点区间resize不覆盖手动选择；回桌面恢复桌面手动偏好。当前采用自动折叠，不增加抽屉；如未来改抽屉，必须统一状态源，不能CSS和组件各管一套。
- resize监听卸载时清理。回归覆盖初始窄屏/跨断点/手动切换/桌面偏好及内容偏移一致。

## 3. 品牌与右上账号区

### 左上角最终样式

**Admin只保留文本 `知序｜管理后台`，不放方形“序”字图标。**

- “知序”：衬线品牌字，22px/600，统一`--font-serif`。
- “管理后台”：小号无衬线功能标识，12px/400，弱文字色；与品牌用细分隔表达层次。
- 品牌链接与顶栏等高，`display:flex; align-items:center; line-height:1`，不靠不同图标基线拼接居中。
- 登录/学习/移动端现有单字标识仍为“序”，品牌名仍为“知序”；本轮仅去掉Admin左上图标，不全站擅自删除。

### 右上角

参考原项目的头像+姓名/角色+下拉：

- 32px Arco Avatar，当前以展示名首字作真实身份占位，不编造照片/在线状态。
- 名字与“管理员”角色上下排列，旁边小下拉箭头。
- 点击展开：**修改密码、退出登录**，可用Arco对应图标。
- 不在顶栏平铺“用户名 / 修改密码 / 退出”一串操作。
- 改密/登出沿用真实路由、会话清理、防重复提交和错误处理，不能为了UI改成假退出。

## 4. 字体体系：在线加载，不打包字体

用户明确选择Google Fonts，不复制本机57MB字体，不引入字体子集构建链，不在项目提交TTF/OTF/WOFF2资源。

配置集中在 **`shared/src/fonts.css`**，双端通过`@quest/shared/fonts.css`引入。

### 默认正文：思源黑体系列

```css
--font-sans: 'Noto Sans SC', 'Noto Sans', 'PingFang SC', 'Microsoft YaHei', system-ui, sans-serif;
```

最终约定是**苹果苹方优先于Windows微软雅黑**。系统正文、表格、表单、弹窗使用该栈，不能只改根字体却让组件库body覆盖掉。

- Arco Less：`font-family: var(--font-sans)`。
- Vant：`--van-base-font`和`--van-price-font`指向`--font-sans`。

### 品牌与宋体区域：思源宋体系列

```css
--font-serif: 'Noto Serif SC', 'Noto Serif', 'Songti SC', 'STSong', 'SimSun', system-ui, serif;
```

原先写Songti/SimSun的品牌、纸张等区域统一使用变量，不留下各页面独立字体栈。**不把整张后台表格改成宋体**。

Footer中仅“知序”使用`brand-wordmark`衬线字体，“· 让学习有迹可循”仍是正文黑体。

### 在线地址

```css
@import url('https://fonts.googleapis.com/css2?family=Noto+Serif+JP:wght@200..900&family=Noto+Serif+SC:wght@200..900&family=Noto+Serif:ital,wght@0,100..900;1,100..900&display=swap');
@import url('https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@100..900&family=Noto+Sans:ital,wght@0,100..900;1,100..900&display=swap');
```

- 只在共享字体样式声明，不在每个Vue页面重复请求。
- `display=swap`，Google不可达时走上述本地降级，不阻塞功能。
- 不把Noto Serif JP放在简体中文SC之前，避免中文字形被日文字体先匹配。
- 公网字体会向Google发字体请求，局域网部署不等于字体离线；严格离线环境需另行选择仅本地降级，不声称字体可离线完整一致。

## 5. Arco主题与样式覆盖

### 主题色

PC当前使用Arco Vue，**通过Less自动生成完整色阶**：

```ts
// pc-web/theme.ts
export const arcoLessOptions = {
  modifyVars: {
    'arcoblue-6': '#087d84',
    'font-family': 'var(--font-sans)',
  },
  javascriptEnabled: true,
}
```

Vite `css.preprocessorOptions.less`使用该配置；按需resolver必须`ArcoResolver({ sideEffect: true, importStyle: 'less' })`。仅设置modifyVars但仍导入css.js预编译CSS，不会应用Less主题。

- less安装于frontend workspace根，避免PC/mobile的Vite可选peer上下文分裂造成类型冲突。
- hover/active/浅色背景等交给Arco色阶，**不手写几档`--color-primary-*`或单独改主按钮背景**。
- 新功能按钮继续使用Arco type/status，不新增一套按钮皮肤。

### 纸张卡片圆角

用户选择**2px圆角**，保留近似纸张的规整感，不做大圆角/装饰阴影。

```css
.admin-shell .admin-users-card.arco-card {
  width: 100%;
  border-radius: 2px;
}
```

Arco无边框卡片默认直角。原`.admin-users-card`和`.arco-card`权重相同，后加载组件样式可能覆盖；用局部组合选择器解决，**不加!important、不全局污染所有.arco-card**。

## 6. 后台列表页模板

从上到下：

1. 面包屑（外层布局提供）。
2. 白色Arco Card，标题是具体页面名“用户管理”。
3. 筛选区：响应式24栅格，横向label，字段与控件对齐。
4. 筛选右侧竖分隔与上下排列的**查询 / 清空**；小屏可换成横排。
5. 横向分隔线。
6. 工具栏：左侧新增，右侧刷新/未来真实的导出等操作。
7. 表格、空态/加载态、流内分页。

- 不在卡片外再放一个巨大H1和说明段落，避免工作区像宣传页。
- 查询/清空/页大小改变回到第1页，翻页保留筛选。
- loading贯穿表单/查询/清空/相关写操作；刷新失败不能把“写入成功”改成失败诱导重复创建。
- 表格按剩余宽度铺满，需要时内部横向滚动，不能把整个页面撑出横向滚动条。
- 操作列使用small text按钮；危险操作用danger，不用大量实心按钮。
- 业务有用字段正常展示；不为了“解释隐私”增加页面说明，不编造数量/成功空表掩盖请求失败。

### 删除的解释性文案（后续不要加回来）

- “管理普通用户的访问资格，不触及用户的私有学习内容。”
- “只列出普通用户账号。时间按北京时间显示；不展示私有题库、题目、附件或对话。”
- “管理员仅管理账号。不提供学习、私有内容访问或模拟用户登录。”
- “使用量统计尚未接入，本页不提供内容预览或模拟登录。”

这些是产品/权限文档内容，不是后台用户需要反复阅读的页面提示。**确认禁用、重置密码等有实际后果的安全提示应保留**，不能一概删除。

## 7. 表单与Modal

- Arco标准Modal，标题左对齐，当前用户表单宽520px。
- 表单横向label与input对齐，当前label 5/24、控件19/24；根据未来字段长度合理调整，不盲目复制。
- 按钮放**Modal的标准`#footer`**，右下“取消 → 主提交”，不在body里额外摆一套底部按钮。
- 提交先调用form.validate，验证通过才写入；支持键盘表单提交，最终写入共用同一方法。
- 请求成功后关闭并刷新，接口/校验失败保留弹窗和输入。
- 请求进行中显示loading、防重复提交、禁用不应关闭的取消/右上关闭；mask不关闭，避免误点丢输入。
- body高度受视口限制并可滚动，不让Footer按钮挤出屏幕。
- 创建/重置/改密仍有完整口令规则；删除“仅创建普通用户，不创建管理员”等无需解释的长文，但保留必要交付/风险提示。

## 8. 登录体验（延续上一轮用户反馈）

- 登录页顶栏与左侧介绍均不放方形Logo；顶栏仅纯文字“知序”，卡片标题中的“知序”使用--font-serif。登录/改密共用.login-page纸张式样和纯文字顶栏，不连带修改学习页面。
- 登录卡片2px圆角、细边框、克制阴影，移除原4px顶部色条；桌面左右分栏，小屏单列，不出现水平溢出。顶部64px、Footer紧凑，保持纸张感与青绿Arco主题。
- 登录不是注册：用户名/密码前端只必填，空值提示“请输入用户名 / 请输入密码”。
- 登录不显示“12–64字符/UTF8<=72字节/空格属于密码”说明，不同时出现灰色desc与红色校验重复文字。
- 账号格式/密码强度属于开户和改密流程；后端认证规则和安全限制不因登录页简化而删除。
- 删除“管理员只管理账号”“不开放自助注册”等内部管理介绍；品牌文案简洁，不解释系统权限架构。
- 登录持久化按用户要求已实现，刷新先经me验证，不显示“刷新页面需重新登录”旧文案；过期/401/登出失效逻辑不变。
- 登录/改密操作结果使用Arco顶部全局Message，不在卡片插入红色Alert导致布局跳动；必填和新密码规则仍在表单项内校验。Message手动引入Less样式确保主题/字体一致；登录消息在新提交/离开页面时关闭，防叠加。
- 登录卡片不显示会话过期条；主动退出后组件新请求只拒绝，不把未登录状态改成“登录过期”。真正到期/401仍清Token与缓存，权限不放宽。
- 改密页与登录页同字体/留白/2px圆角，保留新密码强度/确认密码/首次改密守卫，当前密码仅必填；错误不显示内部英文/traceId。
- 登录401统一显示“用户名或密码不正确”，不枚举账号存在/禁用状态，不把英文异常或traceId直接显示给用户。429显示“登录尝试过于频繁，请稍后再试”，其他登录服务/网络故障显示“登录服务暂时不可用，请稍后重试”，不全部冒充密码错误。底层ApiError仍保留traceId供诊断，未删除服务端日志关联。
